# myRoot v1.0.0 B 方案远端变更单

日期：2026-07-20  
决策：同一生产 MySQL 集群、独立 Candidate schema、独立账号  
当前状态：`PLANNED_NOT_AUTHORIZED`

## 1. 实际输入与缺口

已读取：

1. CloudBase 环境、CloudRun revision、流量、MySQL 实例、备份与只读 SQL 清点。
2. 迁移 `001`～`066`、checksum manifest、schema snapshot。
3. `mysqlRuntimeAlertAuthorityPolicy`、`mysqlRuntimePrincipalBootstrap`、生产迁移与 preflight Implementation。
4. B 方案选择，以及 Candidate schema/账号冲突只读查询。

仍缺：

1. 新鲜的 v1 变更前全量备份及恢复演练证明。
2. Candidate artifact 的不可变 digest、source commit 与 release id。
3. Candidate revision 的精确多 pool 容量预算、0% 定向路由与可证明的 revision identity。
4. 秘密轮换执行授权、各外部凭据轮换顺序与负责人。
5. 现有 `mysqlRuntimePrincipalBootstrap` 仅允许一次性集成测试 schema 与本机 Host，不能用于真实 Candidate；尚缺独立的生产 Candidate 账号规划 Module 与负向测试。

这些缺口不阻塞本变更单设计，但阻塞任何远端写入、部署或放量。

## 2. 目标资源

| 类型 | 目标 | Interface / 权限 |
|---|---|---|
| MySQL 集群 | 现生产 Serverless CynosDB | 共用容量与故障域，不共用 schema 数据 |
| Candidate schema | `root_checkin_candidate_v1` | `utf8mb4 / utf8mb4_unicode_ci`；迁移 `001`～`066` |
| 主运行账号 | `myroot_cand_app`@`%` | schema 级 `SELECT, INSERT, UPDATE, DELETE` |
| 迁移/Definer 账号 | `myroot_cand_definer`@`%` | 迁移期持有迁移权限；迁移后收敛到规定表/过程并锁定 |
| Registrar 账号 | `myroot_cand_registrar`@`%` | 仅规定过程 `EXECUTE`，无直接表 DML |
| Worker 账号 | `myroot_cand_worker`@`%` | 规定过程 `EXECUTE` + 两张规定表 `SELECT` |
| Inspector 账号 | `myroot_cand_inspector`@`%` | 仅规定检查过程 `EXECUTE` |
| Candidate revision | `myroot-api` 的新 revision | 0% 默认流量；`ROOT_MYSQL_MIGRATION_MODE=verify_only` |

账号 Host 采用 `%` 是为了匹配当前 CloudRun 到托管 MySQL 的动态来源 Host；风险由无公网入口、独立强随机秘密和 schema 最小权限共同约束。若平台支持稳定 VPC CIDR Host，创建前应优先把 `%` 缩窄为该 CIDR。

## 3. 必须拆分的授权批次

### B0：秘密事件处置

目标：轮换 revision 详情返回体中暴露的数据库、后台、微信与 CloudBase 秘密，并撤销旧值。

影响：可能短时影响后台访问、Job、微信调用或对象存储；必须按依赖顺序双值过渡或在维护窗口执行。

回滚：仅在新值验证失败且旧值尚未撤销时临时回指旧值；旧值已经暴露，不能作为长期回滚凭据。完成后必须撤销旧值，并更新 secret version digest，不在文档、命令参数或日志中保存原值。

### B1：共享集群保护点

目标：创建 v1 Candidate 变更前全量备份，记录 snapshot id、时间、集群与校验状态；在隔离恢复目标中完成可恢复性校验。

影响：共享集群备份会占用平台资源，但不改业务 schema。

回滚：备份创建失败即停止；不进入 B2。

### B2：Candidate schema 与账号

目标：显式创建 `root_checkin_candidate_v1` 与 5 个专属账号，秘密仅进入平台秘密输入/变量，不进入 shell 参数、仓库或证据。

执行 Interface 必须来自独立的生产 Candidate 账号规划 Module：固定 schema 与 `myroot_cand_*` 账号集合、参数化秘密、禁止任意账号/跨 schema/全局授权、禁止 `GRANT OPTION`，并输出无秘密的计划摘要。不得放宽或复用一次性集成测试 bootstrap 的目标与清理 guard。

影响：修改共享集群 schema 目录和账号目录；不修改生产 schema 表。

回滚顺序：停止 Candidate revision（若存在）→ 删除 4 个运行账号 → 删除并锁定/删除 Definer → 删除 Candidate schema。禁止删除或授权任何非 `myroot_cand_*` 账号，禁止修改生产 schema。

### B3：Candidate 迁移

目标：以 `myroot_cand_definer` 对空 Candidate schema 执行 `001`～`066`，随后校验 ledger 顺序/checksum、结构摘要、过程 Definer 与账号授权，再锁定 Definer。

影响：仅写 Candidate schema，但 DDL 与负载发生在共享生产集群。

停止条件：任一 checksum、顺序、结构、授权、锁等待或容量阈值失败立即停止；MySQL DDL 可能隐式提交，因此失败后不自动继续或假设事务回滚。

回滚：Candidate 无业务数据时按 B2 回滚顺序删除整套 Candidate 专属资源，再从空 schema 重建；不得把半完成 schema 修补为“通过”。

### B4：0% Candidate revision

目标：部署绑定不可变 artifact 的新 revision，配置 Candidate schema 与 5 个账号引用，默认 0% 流量，并通过定向路由验证 revision identity。

必须配置：

1. `ROOT_MYSQL_MIGRATION_MODE=verify_only`。
2. 主 pool、Orchestration、heartbeat、Registrar、Worker、Inspector 各自的连接上限。
3. `MYROOT_CLOUDRUN_MAX_INSTANCES`、`MYROOT_MYSQL_CONNECTION_HEADROOM`、`MYROOT_MYSQL_CAPACITY_EVIDENCE_REF`。
4. Candidate release id、artifact digest、target generation 与 secret version digest。

影响：新增 CloudRun revision 和共享集群连接负载；不切默认生产流量。

回滚：保持 0% 并删除/停用 Candidate revision；撤销 Candidate secrets；如不保留复盘现场，再执行 B2 回滚。

### B5：Candidate 实证

目标：完成 `/ready`、迁移/权限 preflight、跨实例幂等、outbox/inbox、活动/任务/健康/订阅关键路径、容量与告警接收端验证。

容量红线：共享集群当前 `max_connections=1000`、历史峰值 `17` 只作为基线，不是 v1 证明。必须用配置后的各 pool × 最大实例数计算理论上限并在受控负载中实测；出现生产延迟、错误率或连接压力异常立即停止 Candidate 负载。

本批次完成只关闭 Candidate Gate，不授权生产 schema 的 `006`～`066`、生产 revision 部署或流量切换。

## 4. 凭据与日志纪律

1. 不再调用会返回完整 `EnvParams` 的 revision 详情动作，除非输出先在进程内按键名脱敏且原始响应不进入终端/会话。
2. 密码、AppSecret、token、API key 只允许进入平台专用秘密输入或受控 stdin；不得进入命令参数、环境转储、文档、Git 或普通日志。
3. 证据只保留 secret 引用版本摘要、账号名、Host、授权摘要和轮换结果，不保留秘密值。
4. Candidate 与生产不得复用任何数据库或应用秘密。

## 5. 执行前硬 Gate

只有以下全部满足，才可请求 B1～B5 写入授权：

1. B0 轮换方案具名负责人、窗口与撤销顺序已批准。
2. Candidate source commit、artifact digest、release id 和 authorization packet digest 已冻结。
3. 全量备份与恢复目标已明确，恢复演练不会覆盖生产。
4. 账号 Host 选择已由平台网络事实确认；最小权限清单通过离线校验。
5. 独立生产 Candidate 账号规划 Module 及负向测试通过，且清理 Interface 只能命中固定 Candidate 专属资源。
6. 0% 定向路由能证明命中 Candidate revision，而不是仅依赖 `FlowRatio=0`。
7. 容量预算包含全部 pool、最大实例数和生产 headroom。
8. 告警接收人、立即停止负责人和回滚负责人已具名。

当前结论：B 方案结构已确定且无命名冲突；远端状态仍为 `NOT_STARTED`，不得把本文件视为写入授权或上线批准。
