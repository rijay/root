其中 `publicationRequestId` 必须与发布命令的 `requestId` 完全一致，四个 digest 均为 64 位小写 SHA-256，并分别绑定本次活动内容、逐屏 UED 验收、逐资产摄影授权和 **source-only** 工件来源证据。运营人员不得在表单中手填 `operatorId`、`publishOwnerSignerRef`、`verifiedAt` 或授权结论；这些事实必须由受信 Admin principal 和 Publication Authorization Adapter 注入。Adapter 的受控回执至少包含：

```text
authorized: true
adapterId:
decisionRef: globally unique opaque ref
publishOwnerSignerRef:
verifiedAt: ISO-8601 with timezone, not in future, age <= 5 minutes
requestId: exact publicationRequestId
principalOperatorId: exact trusted server principal
activityId:
activityVersionId:
evidence:
  controlledApprovalRef:
  contentAuthorizationDigest:
  uedAcceptanceDigest:
  photographyAuthorizationDigest:
  artifactProvenanceDigest: exact sourceArtifactProvenanceDigest
```

同一 `decisionRef` 不得被多个发布请求复用；回执缺字段、时间窗超限、请求/主体/活动版本不一致或任一 digest 不一致时必须 fail-close。这里的 `sourceArtifactProvenanceDigest` 只证明来源工件，不证明实际部署 image/archive；活动正式发布仍需另行绑定部署 provenance。

验收必须覆盖：报名成功、审核中、拒绝、满额、截止、用户取消、场次取消、重复提交、并发最后名额和人工协助。只有后台查询成功且确实返回 0 条时，才显示真实业务空状态。

### 6.1 机器结构校验 Interface（2026-07-18）

本包现在由 `contracts/content-ued-authorization/v1.0.0.json` 与
`backend/src/contentUedAuthorizationRegistry.js` 提供单一、非运行时结构校验 Interface。该
Module 分别验证 `HEALTH_CONTENT`、`PRIVACY_COMPLIANCE`、
`ACTIVITY_OPERATIONS`、`UED_HANDOFF` 与 `PHOTOGRAPHY_RIGHTS`，并且：

- 只接受 digest、opaque reference、布尔断言、计数和 UTC 时间；公开仓不接收姓名、端点、密钥、原始授权书或可操作 Ardot 标识；
- 显式拒绝空白、占位词、已知占位 digest、缺域、重复职责、撤销签署、过期证据、跨环境拼接和 Candidate/Production 共用环境引用；
- 活动结构只接受实际 Activity Module 使用的 `OPS_BACKEND` 来源枚举，并只校验输入中 `publishedActivityCount >= 1` 的声明；该 Registry 不读取运营后台、Activity Store 或 Candidate 环境，不能验证“至少一项真实活动已发布”的事实，UED 占位不得进入运行时；
- 摄影结构按逐资产 clean master、权利链、微信小程序/商业使用/裁切改图/文字叠加范围、到期责任人与撤销状态验证，并要求 Candidate、UED 与运行时资产全集 digest 一致；
- 完整环境包必须包含五域，完整发布包必须包含相互独立的 Candidate 与 Production 环境包；
- 机器输出只允许为 `STRUCTURE_ONLY_UNTRUSTED_INPUT`；不会输出“Evidence/Gate 已关闭”。seal 复验必须使用不早于封包时间的当前时间和同一撤销快照 digest，过期或撤销快照变化即失败；其所有发布、写入、部署和 Gate 授权始终固定为 `false`。

定向回归命令：`npm run v1:content-ued-authorization:check`；截至 2026-07-18 本地结果为 `13/13 PASS`。测试使用合成 opaque
reference，只验证 Contract/Registry 的结构、时效、职责冲突和资产集合行为，不验证签名密码学真实性、受控审批 Adapter、真实撤销源或 artifact binding。它不构成真实签署、授权、内容发布、摄影使用或 Gate 关闭事实。
