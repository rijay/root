## 1. 评审标准

本轮评审检查的是 ardot 实际落稿，而不是只评审文字方案。

评审维度：

1. 阶段叙事：完成 7 天后是否切换为日常记录，而不是继续强化 7 天任务。
2. 微信规范：导航、触控、反馈、底部行动和权限提示是否符合小程序使用习惯。
3. ROOT 品牌：是否保持暖白、墨黑、苔绿的品牌气质，文案是否温和克制。
4. 主流程可用性：用户能否从首页进入打卡、保存、生成分享图、返回首页。
5. 分享图：是否适合朋友圈和小红书图片流，且不承诺平台自动发布。
6. 字段呈现：身体反馈画像是否只展示参与原因、肠道状态、改善方式。
7. 开发可落地性：是否能从现有页面和数据结构推进，不引入不必要的新 Interface。

## 2. 总体判断

设计方向成立。

Ardot 版本已经把 V0.3.0 的关键叙事从“7 天试饮任务”转为“日常身体记录”。首页、结果页、分享图和历史页都在主信息层级上弱化了 7 天概念；分享图采用保存到相册作为主路径，也符合微信小程序能力限制。

上一轮发现的 P0 问题已经修复：`昨日是否排便` 已补充 `有 / 没有` 二选一控件，并保留 `有排便时展示便型、无排便时隐藏便型` 的实现约束。修复后的今日打卡页已通过 ardot 布局检查。

## 3. 逐屏评审

### 3.1 Daily Home - 今日身体记录

结论：通过。

优点：

- 主标题 `今天，也记录身体反馈` 明确进入日常记录态。
- 统计信息使用 `累计记录 / 当前连续 / 最长连续`，没有继续使用 `N/7`。
- 主按钮 `记录今天` 足够明确，符合单主任务原则。
- 记录历史入口作为次级卡片，不抢主行动。

注意项：

- 开发时需要确认真实小程序 tabBar 的安全区占位，避免首页内容与底部导航距离过近。

### 3.2 Today Record - 日常打卡

结论：通过，P0 已修复。

已成立的部分：

- 顶部使用 `今日记录`，没有把用户带回试饮任务。
- `今日是否服用 ROOT` 使用二选一分段控件，触控面积足够。
- 便型和身体感受区使用卡片分组，视觉阻力比问卷式排布更低。
- 底部主按钮固定为 `保存今日记录`，符合高频记录路径。

已修复：

- 在 `昨日是否排便` 卡片内补充 `有 / 没有` 二选一控件。
- 当选择 `有` 时，展开 `昨日便型` 卡片。
- 当选择 `没有` 时，隐藏便型卡片，并允许继续填写身体感受。
- 选中态必须同时使用颜色和文字，不只依赖颜色。

### 3.3 Result - 今天已记录

结论：通过，P1 可微调。

优点：

- 结果页承接打卡成功后的稳定落点。
- `生成今日分享图` 是主按钮，`返回首页` 是次按钮，层级清楚。
- 摘要卡可读，文案没有确定功效承诺。

P1 建议：

- `累计记录 18 天 当前连续 5 天` 这一区块目前留白偏大，可以在开发稿中收紧高度，或拆为两个并列统计，以减少空卡感。

### 3.4 Share Preview - 今日分享图

结论：通过。

优点：

- 主按钮是 `保存到相册`，符合分享图可靠主路径。
- `微信发送/分享` 作为次级动作，没有承诺直接发朋友圈。
- 说明文案明确 `保存图片后，可自行发布到朋友圈或小红书`，规避平台能力误导。

注意项：

- 开发时需要补齐保存失败、相册权限未授权、重新生成三类反馈。

### 3.5 Poster Template - 1080x1440

结论：通过。

优点：

- 3:4 竖版比例适合小红书和朋友圈图片流。
- 留白、字号和品牌识别都比较克制，不像促销海报。
- 中文日期格式正确：对应年份展示 `5月26日`，非对应年份展示完整年份。
- 没有展示手机号、订单号、地址等隐私信息。

注意项：

- 试饮期分享图的主标题需要另走文案变量：`第 N 天，身体记录已完成`。
- 日常期分享图使用当前稿：`今天，身体记录已完成`。

### 3.6 Record History - 记录历史

结论：通过。

优点：

- `日常记录 / 试饮记录` 分组清晰。
- 日期使用中文格式。
- 试饮期被保留为历史分组，而不是继续作为日常身份。

注意项：

- 开发时列表标题需要根据真实数据切换：试饮期使用 `第 N 天 · 日期`，日常期使用 `今日记录 · 日期` 或 `日常记录 · 日期`。

### 3.7 Profile Tags - 身体反馈画像

结论：通过。

优点：

- 页面只展示参与原因、肠道状态、改善方式。
- 已去掉日常便型状态，符合 V0.3.0 需求。
- 文案改为用户态表达：`已根据入组选择整理，可用于后续记录与顾问沟通。`

注意项：

- `参与原因` 中出现 `7 天记录` 是用户提交内容，可以保留；但不应作为页面系统标题或全局身份标签。

## 4. P0 评审项

### P0-1 今日打卡页缺少“昨日是否排便”选择控件

状态：已修复。

原影响：

- 主流程无法完整表达。
- `hadStool` 与 `stoolType` 的条件关系无法在视觉稿中验证。
- 容易导致开发时把便型做成固定字段，违背“无排便时不展示便型”的需求。

修复结果：

- `昨日是否排便` 必须出现 `有 / 没有` 二选一控件。
- `有` -> 展示便型选择。
- `没有` -> 隐藏便型选择。
- 两种状态都能继续提交身体感受。

验收结果：

- Ardot 已更新并重新导出今日打卡页。
- 今日打卡页布局检查通过。
- `无排便` 分支进入开发拆单验收，开发实现时必须隐藏便型卡片。

## 5. P1 评审项

### P1-1 首页需要补真实 tabBar 占位判断

影响：

- Ardot 首页未展示真实小程序底部 tabBar。
- 如果开发直接套稿，可能忽略底部导航和安全区。

修订标准：

- 开发拆单中明确首页复用现有 tabBar。
- 内容容器底部保留安全区和 tabBar 空间。

### P1-2 结果页统计区可收紧

影响：

- 当前绿色统计区视觉留白偏多。
- 不影响流程，但会显得像未加载完的内容。

修订标准：

- 统计区可改为紧凑胶囊，或两个并列统计项。
- 保持 `累计记录` 和 `当前连续` 的可读性。

### P1-3 分享图需要定义空内容与超长内容状态

影响：

- 当前稿展示的是理想数据。
- 实际用户可能不写身体感受，或写得很长。

修订标准：

- 空身体感受展示：`今天也完成了一次真实记录。`
- 超过 40 字截断并追加省略号。
