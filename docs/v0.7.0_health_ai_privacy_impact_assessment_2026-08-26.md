# myRoot 0.7.0 健康建议隐私影响评估

## 1. 评估结论

2026-08-26 的账户核验确认：CloudBase 大模型日志可保存请求/响应且当前保留 7 天；Chat Completions 缓存不能由客户端控制，公开材料不能证明硬性最长 5 分钟。原“用户完成评测后实时调用模型”的设计因此不能满足项目设定的缓存门禁。

本版本改为“离线合成目录 + 线上本地匹配”：CloudBase AI 只接收 30 个产品预定义的合成状态场景，线上运行时不调用模型、不持有模型密钥、不向模型发送用户个人信息或健康信息。由此，缓存 TTL 不确定性仍是供应商能力事实，但不再承载用户数据，也不再阻塞健康建议功能的个人信息保护评估。

当前综合判断：

- 用户健康数据的模型出网风险：从高风险降为不适用，前提是运行时零模型调用边界持续成立。
- CloudBase 合成内容日志/缓存风险：低风险，仍按 7 天日志、无训练、境内处理和不导出要求管理。
- 健康数据主库、删除、备份、单独同意与真机验证：仍是独立发布门禁，未被本次架构变更关闭。
- 建议目录内容安全：30 条尚未生成和人工审核，正式目录当前保持 `DRAFT`，运行时只会使用固定建议。

## 2. 数据流

### 2.1 内容制作流

```text
冻结的产品分类枚举
  -> 30 个合成组合
  -> CloudBase hy3
  -> PENDING_REVIEW 草稿
  -> 自动结构/禁用表达校验
  -> 人工内容与安全审核
  -> 随候选工件发布的 APPROVED 目录
```

模型请求只含结果代码及静态标签/描述、分类版本、提示词版本和输入版本。生成器拒绝额外字段和未知枚举；不读取用户数据库，也不接受用户请求对象。

### 2.2 用户运行流

```text
用户主动完成两项评测
  -> myRoot 服务端保存结果
  -> 仅用两个结果代码查本地审核目录
  -> 命中则展示经审核目录建议
  -> 目录不完整/未审核/无效则展示固定建议
```

运行流没有 CloudBase AI、模型地址、模型 API Key、模型日志或模型缓存。

## 3. 必要性与最小化

- 用户评测数据用于完成评测、保存历史、回测和选择建议，目的明确。
- 模型内容制作不需要真实用户数据；使用固定分类枚举已经足以生成候选文案。
- 线上只使用两个结果代码完成目录选择，问卷答案、结果标题、问卷版本、身份标识和安全分流标记均不进入目录 Interface。
- 合成目录不用于用户画像、自动化决策或诊断，仅提供低风险生活方式建议候选；内容必须人工审核。

## 7. 发布决策

### 可以继续

- 运行时固定建议链路和目录 fail-close 联调。
- 使用模拟模型响应验证 30 个合成组合、草稿结构和审核门禁。
- 在另行确认外部调用及可能费用后，用 CloudBase 生成合成目录草稿。

### 尚不可宣称完成

- “AI 辅助生成，经审核”的正式目录：尚未执行 30 次外部生成，也未人工审核。
- 0.7.0 候选/体验版/生产：仍需健康数据删除、备份、真机隐私流程、目录工件与发布证据。

### 正式目录放行条件

1. 30 个合成场景全部生成且没有真实用户数据。
2. 30 条逐条人工审核并记录审核人和时间。
3. 正式目录文件与候选工件摘要一致。
4. 生产环境不存在健康建议模型地址或 API Key。
5. 候选环境证明运行时模型请求数为 0，目录缺失时固定建议降级成立。
6. `ROOT_HEALTH_ADVICE_CATALOG_VERSION=root4u-health-advice-catalog-v1` 与 `ROOT_HEALTH_ADVICE_CATALOG_REVIEWED=true` 有后台 VERIFIED 记录和可回读证据。

## 8. 腾讯云工单记录

- 工单号：`202608267340`
- 用户反馈摘要：输入、输出、日志和缓存不用于训练等二次用途；日志保留可自行设置；无其他受托方或跨境；业务侧自行管理删除；无需补充算法备案材料。
