## 2. 评估依据与判定口径

### 2.1 法规口径

健康信息属于敏感个人信息。处理敏感个人信息应具有特定目的和充分必要性，采取严格保护措施，履行单独同意和额外告知义务。委托处理应约定处理目的、期限、方式、信息种类、保护措施和双方权利义务，并监督受托人；处理敏感个人信息、委托处理及可能产生重大影响的处理活动，应事前开展个人信息保护影响评估，评估记录至少保存三年。个人信息保存期限原则上应为实现处理目的所必要的最短时间。网络安全日志按现行网络安全法至少保存六个月，应用运行日志和健康内容不因此混同保存。

## 3. 角色与处理链路

### 3.1 角色

| 角色 | 当前识别 | 结论 |
| --- | --- | --- |
| 个人信息处理者 | myRoot 小程序实际运营主体 | 仓库未载明签约法定主体全称，审批前必须由业务/法务补全 |
| 受托处理方 | 腾讯云 CloudBase AI 的合同签约主体 | 公开文档不能确定本账户订单对应的法定主体，必须以订单、服务协议或数据处理协议为准 |
| 模型提供方 | 腾讯混元，模型 ID `hy3` | CloudBase 官方模型文档和当前账户只读模型列表均支持该结论 |
| 可能的其他受托方 | 日志、缓存、基础设施或模型服务关联方 | 公开材料不足，需腾讯云书面列明是否存在及其地域、职责 |

### 3.2 数据流

1. 用户在 myRoot 完成两类健康评测；原始答案和评测结果保存在 myRoot 服务端。
2. 后端仅从两个已完成结果生成四个外发派生状态字段，不发送手机号、微信标识、用户 ID、评测记录 ID、安全分流标记、原始答案或自由文本；这些字段已经显著缩减，但是否达到严格最小仍需按第 7 节关闭。
3. 出网适配器再次按四字段白名单校验两类评测状态，丢弃任何额外字段并拒绝缺项、重复类型或无效值；随后以 HTTPS 调用 CloudBase AI 的 OpenAI 兼容接口，模型为 `hy3`，API Key 仅进入 `Authorization` 请求头。
4. CloudBase AI 返回结构化健康建议；后端执行固定字段、长度和医疗禁用词校验。超时、网络错误或格式无效时使用已审核的本地降级文案。
5. 通过校验的建议与输入状态、来源及版本信息保存为 `healthAdviceSnapshots`，用于向当前用户展示及追溯。
6. CloudBase 具备调用日志和服务端缓存能力。myRoot 正式数据规范要求请求/响应日志最长保留 7 天、服务端临时缓存最长 5 分钟；运行时只有在 `SECONDARY_USE=NONE`、`PROCESSING_REGION=CN_MAINLAND`、`OTHER_PROCESSORS=NONE`、日志为 7 天、缓存为 5 分钟且配置已核验时才允许调用模型。账户日志已满足 7 天上限，但 Chat Completions 缓存不能由客户端控制，当前账户页也没有 TTL 配置，官方价格文档还说明缓存失效没有明确规则，因此模型仍保持关闭。

## 4. 数据清单与必要性

| 数据 | 是否发送模型 | 用途 | 当前控制 | 判定 |
| --- | --- | --- | --- | --- |
| 原始问卷答案 | 否 | 内部形成评测结果、回测记录 | 服务端保存；用户可删除评测 | 不进入供应商链路 |
| 用户标识、手机号、微信标识 | 否 | 内部鉴权和数据归属 | 模型适配器不接收这些字段 | 不进入供应商链路 |
| `inputVersion` | 是 | 标识静态请求结构版本 | 不含个人信息 | 功能相关 |
| `assessmentType` | 是 | 区分健康起点/肠道自测 | 固定枚举 | 功能相关 |
| `questionnaireVersion` | 是 | 解释结果版本 | 固定版本号 | 是否影响生成结果尚未验证 |
| `resultCode` | 是 | 表示评测归类 | 派生编码，不含原始答案 | 功能相关 |
| `title` | 是 | 给模型提供可读状态语义 | 可能直接表达健康状态，并与结果代码部分重叠 | 需要保留理由或改由服务端静态映射 |
| `safetyStopped` | 否 | 内部安全分流和建议快照追溯 | 任何值为 `true` 时根本不调用模型 | 已从模型外发接口删除 |
| 静态系统提示词 | 是 | 限定非诊断、固定 JSON 输出 | 不包含用户信息 | 必要 |
| 模型生成建议 | 供应商生成并回传 | 展示状态与生活方式建议 | 服务端校验，失败降级；供应商日志最长 7 天、临时缓存最长 5 分钟 | 必要；日志项已满足，缓存硬性上限仍待证明 |
| 建议快照及版本信息 | 否，保存在 myRoot | 展示、追溯、版本一致性 | 删除关联评测时同步删除；到期后由健康数据留存任务整条删除 | 必要；候选数据库与定时任务仍待验证 |

模型请求未携带直接账户标识，但内容反映个人健康状态，且 myRoot 内部仍能把请求结果关联回具体用户。本评估按**经过最小化/去标识化的敏感个人信息**处理，不将其视为已经匿名化的数据。

## 8. 综合判断

### 8.1 合法性、正当性与必要性

健康建议功能有明确用户目的；当前只发送两个评测的四个派生状态字段，且高风险停止、固定输出和本地降级显著降低了数据及健康安全风险。安全分流标记已从外发接口删除，出网适配器也会丢弃额外字段，现有设计具备继续本地验证的基础；其余字段仍需按 PIA-11 验证，不能把当前字段表述为已经证明的严格最小集。问卷答案、评测结果、维度、安全状态、回测内容和建议现已统一采用 180 天上限，到期后不再保留可重生成建议的健康内容。

模型供应商侧具备保存请求和响应内容的能力。账户实配已确认大模型日志当前保存 7 天，项目负责人决定将其作为最长保存期限；通过四字段最小输入、无直接身份标识、用途限制、到期删除、v7 单独同意和禁止延长/导出来控制风险。项目同时接受服务端临时缓存最长 5 分钟，但 Chat Completions 协议不能由客户端控制，账户页没有 TTL 配置，官方价格文档也说明缓存失效没有明确规则。因此继续以运行时、生产环境矩阵和证据发布记录三层门禁保持模型关闭；在最长不超过 5 分钟获得账户、订单、协议或产品条款证据前，不能批准正式环境模型调用。

### 8.2 发布决策

- **可以继续**：在开发者工具/本地环境验证接口约束、同意页面、失败降级和经专业审核的固定建议；测试材料不得包含真实用户健康数据。
- **可以单独评审**：若产品决定正式环境只使用经专业审核的本地固定建议，且模型适配器保持关闭，可另行完成内容、隐私文案、真机和正式数据留存验收；这不等于模型路径通过。
- **不得进行**：在账户日志 7 天到期、缓存最长 5 分钟硬性证据、固定数据策略值、订单/协议主体、候选删除/备份演练和凭据整改证据完成前启用 CloudBase AI，或设置 `ROOT_CUTOVER_HEALTH_ADVICE_MODEL_VERIFIED=done`。
