# myRoot v0.8.0 本地候选说明

日期：2026-08-31

状态：`LOCAL_CANDIDATE / VERIFY_PASS / NOT_PUSHED / NOT_UPLOADED / NOT_DEPLOYED`

## 1. 本版目标

v0.8.0 聚焦两件事：清理小程序与服务端已废弃、重复的运行时逻辑；接通 Root 会员商城的商品实时价格、订单和优惠券摘要及跨小程序跳转。目标是让后续迭代只依赖一条健康评测链路和一组边界清晰的会员商城 Interface，避免旧实现回流或把缓存价格误当实时价格。

本版只覆盖 myRoot 小程序与其 API 运行面。仓库根包、Admin 和独立 Job 仍属于既有 `0.5.13` 发布列车，不随本次小程序功能版本改号；不能把它们的历史发布证明当作 v0.8.0 的候选或生产证明。

## 2. 运行时债务清理

1. 健康评测的目录、开始、草稿、完成、历史、删除和对比统一走服务端 Interface。
2. 删除客户端本地健康评测、本地留存、未注册页面和只验证旧实现的测试。
3. 服务端 `v060Api` 更名为版本无关的 `myrootApi`，开发种子改用独立 fixture，不再耦合小程序运行时实现。
4. 保留历史数据库迁移、历史数据读取、安全兼容逻辑、Root4U 后台能力和离线商品基础信息。
5. 新增反向护栏，阻止 Day4/Day8 标识、旧双存储模式、`LOCAL_V060_COMPAT` 和 `v060Api` 回流。

详细边界见 [v0.8.0 运行时代码清理记录](./evidence/v0.8.0_runtime_debt_cleanup_2026-08-30.md)。

## 3. Root 会员商城接入

1. 商品页通过服务端读取有赞商品详情，展示实时价格、SKU 快照、库存状态和明确的价格来源；接口失败时保留官方基础商品，但不标记为实时价格。
2. “我的”页只展示订单总数、待处理订单数、可用优惠券数、近七天到期数量和同步时间，不向小程序下发订单号、金额、地址、券码、手机号或有赞会员标识。
3. 会员摘要只接受服务端验证过 provenance 的微信 UnionID，并要求唯一映射 Root 会员；零条或多条映射均失败关闭。
4. 商品购买优先使用服务端授权跳转目标，网络或记录失败时回退到随包官方目录目标；AppID、路径、query key 和短链均使用白名单校验。
5. 商品快照和会员摘要使用短时进程内缓存，避免第三方突发调用；缓存不会被表述为实时查询结果。
6. 正式环境矩阵要求只读有赞 token 与 ROOT 店铺 kdt/grant id，缺少任一关键配置时保持阻塞。

详细契约见 [v0.8.0 Root 会员商城接入记录](./evidence/v0.8.0_member_center_commerce_2026-08-31.md)。

## 5. 外部验收与停止规则

1. CloudBase 候选服务必须使用受控密钥注入只读有赞 token 和 ROOT 店铺标识，只回读配置存在性，不输出密钥。
2. 必须确认正式有赞应用具有商品、会员、订单和优惠券只读权限，并确认正式出口 IP 白名单。
3. 必须使用明确授权的测试会员验证可信 UnionID 唯一映射与最小摘要，不得用原始问卷答案或联系方式做客户端联表。
4. 体验版需至少在一台 iOS 和一台 Android 真机验收商品价格、摘要、四类跳转、返回恢复和失败重试。
5. 服务端候选部署、体验版上传、微信审核、正式发布和流量切换是独立 Gate；任一 Gate 未通过时不得沿用本地结论宣称已上线。
6. 本地提交不会自动 push、tag、上传、部署或修改线上配置；这些动作需后续单独授权。
