# myRoot 0.7.0 健康 AI 数据管理规范

## 1. 文档信息

- 版本：`myroot-health-ai-data-2026-08-26-v4`
- 适用范围：健康起点评测、肠道健康 5 道题自测、评测历史、回测对比、健康建议目录制作与运行时建议匹配
- 适用地域：中国大陆
- 核心边界：CloudBase AI 仅用于离线生成产品预定义的合成内容；线上用户请求不调用模型，不向模型发送个人信息或健康信息

本规范是产品、研发、内容审核、运维和个人信息保护负责人的内部控制基线。腾讯云关于日志保留 7 天、无训练、境内处理等反馈继续归档，但 CloudBase 的缓存 TTL 不再作为用户健康数据上线门禁，因为缓存中不得出现任何用户数据。

## 2. 数据流和禁止事项

### 2.1 离线内容制作

1. 输入固定为 6 个健康起点结果代码与 5 个肠道结果代码的笛卡尔积，共 30 个合成场景。
2. 每次请求只包含两个结果代码、对应的产品固定标签/描述、目录/提示词/分类版本；这些内容来自代码中的冻结枚举，不来自任何用户请求或数据库记录。
3. 生成器拒绝额外字段、未知结果代码和重复覆盖已有草稿；API Key 只从本地钥匙串读取。
4. 输出先写入权限为 `0600` 的新草稿，全部标记 `PENDING_REVIEW`。草稿不得被线上运行时读取。
5. 30 条内容必须逐条通过结构、长度、医疗禁用表达和人工内容安全审核，记录审核人、审核时间和版本后才能进入正式目录。

### 2.2 线上运行时

1. 运行时只读取随候选工件发布的正式目录；不得配置或读取健康建议模型 API Key。
2. 服务端仅使用两项评测的结果代码进行本地目录匹配，不发起模型网络请求。
3. 目录不是 `APPROVED`、不是 30/30 条、任一条未审核、重复、缺失或未通过内容校验时，整个目录 fail-close，使用经审核固定建议。
4. 安全停止分支始终使用经审核安全文案，不进入普通建议目录。
5. 用户删除任一关联评测时，对应建议快照一并删除；已删除或到期结果不得再次触发建议匹配。

### 2.3 明确禁止

- 禁止把姓名、手机号、微信标识、用户 ID、评测记录 ID、问卷版本、结果标题、原始答案、自由文本、安全分流标记、用户请求日志或任何从真实用户记录派生的载荷发送给模型。
- 禁止线上运行时加载 CloudBase 模型地址或 API Key。
- 禁止把模型草稿、未审核内容或部分审核目录发布给用户。
- 禁止在应用日志中记录健康载荷、建议正文、API Key、Authorization、openid、unionid 或手机号。

## 3. 数据生命周期

| 数据类别 | 保存位置 | 最长保存期限 | 到期或删除动作 |
| --- | --- | --- | --- |
| 问卷答案、评测结果、维度、安全状态、回测内容 | myRoot 在线主库；开发者工具模式仅在本机 | 自最后保存起 180 天 | 清除健康内容并标记到期；不再展示、对比或匹配建议 |
| 用户建议快照及关联状态副本 | myRoot 在线主库 | 自生成起 180 天；删除任一关联评测时立即失效 | 整条删除 |
| 应用调试与运行日志 | myRoot 日志平台 | 30 天 | 自动删除；禁止健康载荷与直接身份标识 |
| 网络安全、访问和删除审计 | 境内安全日志平台 | 180 天至 1 年 | 到期删除或不可逆匿名化 |
| 加密滚动备份 | 中国大陆境内备份存储 | 30 天 | 滚动覆盖；恢复前重放删除清单 |
| 同意、撤回和删除请求事实 | 受控审计存储 | 处理结束后至少 3 年 | 到期销毁；不保留健康内容 |
| 合成目录生成请求/响应日志 | CloudBase AI | 7 天 | 到期自动删除，不延长或导出；内容不得来自用户 |
| 合成目录服务端缓存 | CloudBase AI | 平台控制，客户端不能承诺硬性 TTL | 仅允许缓存合成场景；不得因此接收用户数据 |
| 目录草稿 | 本地受控临时文件 | 完成审核或终止后 30 天内 | 安全删除；不得进入线上运行目录 |
| 已审核目录与审核证据 | 版本库及受控发布档案 | 目录在用期间及停用后至少 3 年 | 按档案制度销毁 |

用户删除、撤回同意或注销时，在线健康数据最迟 24 小时内删除，备份随 30 天周期清除。因为模型供应商从未接收用户数据，该操作不产生供应商侧个人信息删除请求；这不影响 myRoot 对在线主库、日志和备份的删除责任。

## 4. CloudBase 使用约定

- 模型：腾讯混元 `hy3`，通过 CloudBase OpenAI 兼容接口，仅供离线内容制作。
- CloudBase 日志保留：维持 7 天，不延长、不导出、不复制到其他日志系统。
- 二次用途：输入、输出、日志和缓存不得用于训练、微调、标注、评测或产品改进。
- 地域与其他处理方：限定中国大陆，不增加其他受托方或跨境处理；变更时暂停目录生成并复核。
- 缓存：Chat Completions 的缓存失效由底层模型控制。项目不再把无法证明的“最长 5 分钟”当作个人信息保护措施，而是在数据进入前通过“仅合成内容”消除个人信息风险。
- API Key：只允许存在于本地受控钥匙串或专用内容制作环境；不得进入生产/体验版/真机运行配置、仓库、草稿或日志。

## 5. 审核和发布门禁

正式目录必须同时满足：

1. `schemaVersion=1`，目录、分类和提示词版本与代码常量一致。
2. 30 个固定组合各出现一次，不多、不少、不重复。
3. 每条 `reviewStatus=APPROVED`，目录整体 `reviewStatus=APPROVED`。
4. `generatedAt`、`reviewedAt`、`reviewer` 与 `modelName` 完整。
5. 固定结构、长度和医疗禁用表达自动校验全部通过。
6. 内容审核记录、目录文件摘要和候选工件证据可回读。
7. 运行时验证没有模型地址、模型密钥或模型网络请求。

生产配置只保留：

```text
ROOT_HEALTH_ADVICE_CATALOG_VERSION=root4u-health-advice-catalog-v1
ROOT_HEALTH_ADVICE_CATALOG_REVIEWED=true
```

这两个值只是声明，不能替代 30/30 审核记录和候选工件证据。目录未达门禁时，固定建议路径可继续测试；不得把降级路径表述为目录已经生成或审核。

## 6. 事件与权利响应

- 发现真实用户数据进入目录草稿、模型请求、供应商日志或缓存时，立即停止生成，隔离相关文件和凭据，并在 2 小时内通知研发、安全和个人信息保护负责人。
- 24 小时内确认范围、数据类别、供应商日志窗口、受影响主体和清除路径；依法需要通知或报告时由责任主体执行。
- 用户查阅、更正、删除、撤回和注销继续按 myRoot 健康数据流程处理；合成目录不是用户画像，不包含可响应到个人的数据。
