# 重构 Backlog 与验收

## 1. 倒排顺序

### R0：冻结事实与测量（1–2 天）

- 重新回读 `main`、微信开发版本/审核/发布状态、CloudBase 当前版本与流量。
- 用真机记录登录和首页请求瀑布、阶段耗时、错误率和截图。
- 从 Ardot 导出 CURRENT 只读交付包。
- 冻结旧 7 日计划回归用例和测试数据。

退出条件：有可重复的性能基线、设计基线和线上状态快照。

### R1：视觉底座和 App Shell（2–4 天）

- Design System Module：Token、排版、按钮、卡片、状态、影像容器。
- 五 Tab 图标、安全区、导航和骨架屏。
- 两屏品牌引导与 Guest 首页。
- 建立 320/375/390/430px 截图回归。

退出条件：无需业务数据也能完整展示设计壳；与 CURRENT UED 逐屏对照通过。

### R2：Session 与首页性能（3–5 天）

- 抽出 Session Module，保持现有登录修复。
- 后端增加 Home Experience 深查询 Interface。
- 本地快照、请求合并、取消和局部错误降级。
- 加入阶段性能埋点和 correlation id。

退出条件：首屏关键请求 ≤ 2；P95 达到性能预算；登录失败/超时/重试全通过。

### R3：商品、活动、任务、我的（5–8 天）

- 依次迁移商品列表/详情、活动列表/详情/报名、任务中心/详情、奖励、我的。
- 真实活动内容全部来自运营后台，设计数据仅作占位。
- 旧 7 日计划通过 Legacy Adapter 投影到新任务 Interface。

退出条件：五 Tab 不再依赖旧首页多分支；写动作并发与结果未知测试通过。

### R4：健康纵向流程（Gate 后 4–7 天）

- 成人资格、独立同意、分类、评测、结果、建议、历史与安全阻断。
- 健康内容、隐私和人工协助完成具名验收后才开启。

退出条件：拒绝/撤回可继续非健康功能；红旗路径和数据隔离测试通过。

### R5：灰度与退役（2–4 天）

- Candidate 只读核验、迁移预检、条件灰度、性能和业务对照。
- 稳定后移除旧 UI 分支；保留必要数据 Adapter 和回滚版本。

退出条件：发布、审核、流量和回滚分别有证据；无“页面存在即完成”的假验收。

## 2. 前端验收矩阵

| Gate | 必须证明 |
| --- | --- |
| UED | CURRENT 页面、所有 Variant、交互、空/错/恢复、真机截图 |
| 性能 | 冷/热启动和登录 P50/P90/P95；请求数与慢请求 |
| 身份 | 协议、登录、待关联、人工协助、身份恢复、退出 |
| 健康 | 同意/拒绝/撤回、成人资格、红旗阻断、数据最小化 |
| 活动 | 草稿不公开、满员、截止、审核、取消、并发最后名额 |
| 任务/奖励 | 重复提交、结果未知恢复、奖励不重复、旧计划兼容 |
| 资产 | clean master、裁切、授权、失败替代、无 PANE 资产 |
| 可访问性 | 字号、对比度、动态状态提示、触控区和安全区 |

## 3. 后端验收矩阵

- 每个 Module 的 Interface、鉴权、错误模式和性能特征有文档与合同测试。
- `app.js` 不再承载领域 Implementation。
- 首页聚合读模型的局部失败、缓存版本和降级有测试。
- 写动作继续使用独立 request id、idempotency key、Outbox/Inbox 和权威结果查询。
- MySQL Adapter 和内存测试 Adapter 的事实一致性有契约测试。
- 普通分析、业务审计和健康敏感记录物理/逻辑隔离。
- Candidate 使用真实 MySQL、真实微信身份和受控提醒，但测试数据与生产用户隔离。

## 4. 对抗式审查：最容易再次翻车的五点

1. **只换皮不降复杂度**：把旧首页拆成多个视觉 Module，但仍由一个页面知道全部状态。修正：先冻结 Home Interface，再迁移 UI。
2. **为速度绕过正确性**：删除幂等、结果未知恢复或健康 Gate。修正：性能优化只改变读路径和渲染，不削弱写合同。
3. **直接塞入大图**：用原始 PNG/PDF 追求视觉还原。修正：内容/CDN、多尺寸裁切和权利验收先行。
4. **旧文档再次主导开发**：从四 Tab 或旧 7 日品牌化稿继续。修正：新任务先读交接包和 CURRENT Design/PRD。
5. **把上传当发布**：版本号、开发版、体验版、审核、发布和 CloudBase 流量混淆。修正：每一 Gate 单独回读与记录。

## 5. Definition of Done

重构不是“所有页面能打开”，而是同时满足：

- 设计：CURRENT UED 逐屏通过；
- 体验：关键性能预算通过；
- 产品：五 Tab 职责和核心旅程通过；
- 正确性：身份、健康、活动、任务、奖励合同通过；
- 运营：内容由后台管理且有审核/回滚；
- 发布：CI、Candidate、真机、微信审核与线上状态分别有证据。
