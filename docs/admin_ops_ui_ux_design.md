# ROOT 后台运营工作台 UI/UX 设计方案

版本：V0.2
日期：2026-05-24
状态：P0 修订完成，可进入开发拆单
范围：`http://127.0.0.1:8787/admin` 后台信息架构、页面结构、运营工作流与视觉规范

## 0. P0 修订记录

本版吸收 [admin_ops_ui_ux_design_review.md](./admin_ops_ui_ux_design_review.md) 的 P0 评审结论，完成以下修订：

1. 订单匹配从单一表单调整为“搜索、预览、确认、写入”四步流程。
2. 订单匹配 tab 拆分为“录入/更新订单”和“匹配给用户”两个模式。
3. 今日运营指标补充明确数据来源，首版只使用现有后台数据或轻量扩展字段。
4. 订单匹配里的“导入有赞样本”改为“批量粘贴订单”，与开发与发布 tab 的“真实样本导入”区分。
5. 外部联系动作改为“复制跟进话术、标记已联系、生成跟进待办”，不承诺系统自动触达用户。

## 1. 设计目标

将现有后台从“开发验收与数据面板”重构为“ROOT 小程序运营工作台”。

核心目标：

- 运营者进入后台后，优先看到今天要处理的人、订单、免单和异常反馈。
- ROOT 品牌感与小程序一致，但后台保持高信息密度和高操作效率。
- 开发、发布、Adapter、样本校准等内容独立收纳，避免干扰日常运营。
- 手动匹配有赞订单成为明确、可回溯、可防错的运营动作。

## 2. 设计原则

### 2.1 运营优先

后台默认首页不展示开发校准信息，而是展示今日运营状态：

- 谁今天没打卡。
- 谁反馈异常。
- 哪些订单需要匹配。
- 哪些用户已送达但未开始。
- 哪些免单待审核。

### 2.2 ROOT 品牌一致

视觉延续小程序的 ROOT 品牌语言：

- 暖白背景。
- 苔绿主色。
- 墨黑文字。
- 米灰分隔。
- 少量琥珀色用于提醒。

不使用强营销感大图 hero。后台应克制、清晰、可扫描。

### 2.3 行动导向

每个页面区块都需要回答：

- 当前发生了什么。
- 为什么需要处理。
- 下一步运营该点哪个按钮。

### 2.4 开发内容隔离

Adapter 校准、上线闸口、发布记录、真实样本导入保留，但全部进入「开发与发布」tab。

## 3. 页面全局结构

### 3.1 顶部结构

顶部固定为轻量工作台头部：

- 左侧：ROOT logo + `运营工作台`
- 中间：一级 tab
- 右侧：环境标识、本地/云托管状态、刷新按钮

建议文案：

- 标题：`ROOT 运营工作台`
- 环境标识：`本地环境` / `云托管环境`
- 刷新按钮：`刷新数据`

### 3.2 一级 tab

后台采用 6 个一级 tab：

| Tab | 默认排序 | 目标用户 | 核心任务 |
| --- | --- | --- | --- |
| 今日运营 | 1 | 运营者 | 看今天要处理什么 |
| 用户管理 | 2 | 运营者 | 搜索用户、查看详情、发起跟进 |
| 订单匹配 | 3 | 运营者 | 手动匹配有赞订单与小程序用户 |
| 打卡与反馈 | 4 | 运营者 | 查看打卡、问卷、异常反馈 |
| 免单与售后 | 5 | 运营者 | 处理免单审核和售后异常 |
| 开发与发布 | 6 | 开发者/管理员 | 查看上线闸口、Adapter 和发布记录 |

默认进入：`今日运营`。

| 层级 | 建议 |
| --- | --- |

## 5. 今日运营 tab

### 5.1 页面目标

运营者打开后台第一眼知道今天的状态和待办优先级。

### 5.2 页面结构

1. 今日指标条
2. 高优先级待办
3. 订单匹配提醒
4. 免单待审
5. 异常反馈
6. 已送达待开始

### 5.3 今日指标

指标建议：

- 今日应打卡
- 今日已打卡
- 今日未打卡
- 待处理任务
- 待匹配订单
- 待审核免单
- 已送达待开始
- 异常反馈

首版数据定义：

| 指标 | 数据定义 | 备注 |
| --- | --- | --- |
| 今日应打卡 | `summary.dueToday` | 复用今日 Summary |
| 今日已打卡 | `summary.checkedToday` | 复用今日 Summary |
| 今日未打卡 | `summary.missedToday` | 复用今日 Summary |
| 待处理任务 | open operation tasks | 默认只看未完成待办 |
| 待匹配订单 | `youzanOrders` 中无 `user_id` 的订单 | 用于跳转订单匹配 |
| 待审核免单 | `refundWorkItems` 中 `PENDING` 的工作项 | 用于跳转免单与售后 |
| 已送达待开始 | `readyToStartUsers` | 订单已送达但未开始打卡 |
| 异常反馈 | high severity feedback 或 `FEEDBACK_FOLLOW` 待办 | 首版可先以待办近似 |

指标交互：

- 点击 `今日未打卡`，筛选待办列表为未打卡提醒。
- 点击 `待匹配订单`，跳转到订单匹配 tab。
- 点击 `待审核免单`，跳转到免单与售后 tab。
- 点击 `已送达待开始`，筛选待办或跳转用户管理。
- 点击 `异常反馈`，跳转打卡与反馈 tab。

### 5.4 高优先级待办

列表字段：

- 优先级
- 待办类型
- 用户昵称/手机号
- 触发原因
- 建议动作
- 状态
- 操作

操作：

- `查看用户`
- `复制跟进话术`
- `标记已联系`
- `生成跟进待办`
- `标记完成`
- `跳过`

优先级排序：

1. 物流异常
2. 订单冲突
3. 异常反馈
4. 免单待审
5. 已送达未开始
6. 今日未打卡
7. 优惠券未使用

### 6.3 用户列表

列表字段：

- 用户

- 当前状态
- 最近打卡日期
- 累计记录

- `查看详情`

## 7. 订单匹配 tab

### 7.1 页面目标

让运营者可以手动匹配有赞订单，解决自动匹配失败、手机号不一致、订单未同步等问题。

### 7.2 页面结构

订单匹配 tab 采用三列工作台：

1. 左列：订单搜索、订单详情、录入/更新订单。
2. 中列：用户搜索、用户详情、候选用户列表。
3. 右列：匹配预览、风险提示、确认写入、成功反馈。

### 7.3 两个操作模式

订单匹配拆成两个模式，避免把订单录入和用户绑定混成一个动作。

#### 模式一：录入/更新订单

目标：

- 把有赞订单写入后台。
- 允许暂不绑定用户。
- 适用于有赞订单未同步、运营临时补录、批量粘贴订单后的修正。

关键动作：

- `搜索订单`
- `录入新订单`
- `更新订单信息`
- `批量粘贴订单`

成功反馈：

- `订单已录入`
- `订单已更新`
- `当前未绑定用户，可继续匹配给用户`

#### 模式二：匹配给用户

目标：

- 将已有订单绑定到小程序用户。
- 处理手机号一致、手机号不一致、订单已绑定、用户已有活跃订单等风险。

关键动作：

- `选择订单`
- `选择用户`
- `预览匹配`
- `确认匹配`
- `确认改绑`

成功反馈：

- `订单已匹配`
- `已关联用户：{昵称} {手机号}`
- `后续动作：生成已送达待开始 / 等待物流送达 / 生成物流异常待办`

### 7.4 四步匹配流程

订单匹配按四步执行：

1. 搜索：输入订单号、收货手机号、用户手机号或用户昵称。
2. 预览：并排展示候选订单、候选用户和匹配风险。
3. 确认：运营选择匹配动作，并填写运营备注。
4. 写入：提交成功后展示后续动作。

预览区必须展示：

- 用户昵称、用户手机号、当前状态。
- 有赞订单号、收货手机号、商品、金额、物流状态。
- 风险提示。
- 写入后动作：仅绑定订单 / 生成已送达待开始 / 生成物流异常待办。

### 7.5 搜索与创建区

搜索输入：

- 有赞订单号
- 收货手机号
- 用户手机号
- 用户昵称

快捷按钮：

- `搜索`
- `新建手动订单`
- `批量粘贴订单`

`批量粘贴订单`说明：

- 用于运营临时把有赞订单写入后台，并参与订单匹配。
- 支持从有赞导出的表格复制订单行。
- 不展示 Adapter 准入、状态映射、取样评审等开发内容。
- 开发/管理员校准平台字段时，仍进入「开发与发布」tab 使用`真实样本导入`。

### 7.6 订单录入字段

字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 有赞订单号 | 是 | 用于去重 |
| 收货手机号 | 是 | 用于推荐用户 |
| 收货人 | 否 | 帮助运营确认 |
| 商品名称 | 否 | 默认 ROOT 7日试饮装 |
| 实付金额 | 否 | 用于免单审核 |
| 订单状态 | 是 | 默认已支付 |
| 物流状态 | 是 | 未发货、已发货、已送达、异常 |
| 运单号 | 否 | 物流追踪 |
| 关联用户 | 否 | 可搜索后选择 |
| 运营备注 | 否 | 审计与交接 |

### 7.7 匹配防错规则

- 订单号已存在时，进入“更新订单”模式，不重复创建。
- 订单已绑定其他用户时，展示红色冲突确认。
- 用户已有活跃试饮订单时，展示风险提示。
- 收货手机号与用户手机号不一致时，需要二次确认。
- 物流状态为已送达时，匹配后自动进入“已送达待开始”。
- 物流状态为异常时，匹配后生成售后待办。
- 订单已绑定其他用户时默认阻止，除非运营选择`确认改绑`。
- 有风险时不能直接提交，必须先经过匹配预览和二次确认。

### 7.8 匹配确认区

确认区内容：

- 匹配动作：绑定订单 / 改绑订单 / 仅更新订单。
- 风险摘要：手机号不一致、用户已有活跃订单、订单已绑定其他用户。
- 运营备注。
- 写入后动作说明。

确认按钮：

- 无风险：`确认匹配`
- 有风险：`我已核对，确认匹配`
- 改绑：`确认改绑`

### 7.9 匹配成功反馈

成功后按钮：

- `查看用户详情`
- `继续匹配下一单`
- `返回今日运营`

## 9. 免单与售后 tab

### 9.1 页面目标

让运营者完成免单审核和售后异常处理。

### 9.2 免单审核列表

字段：

- 用户
- 有赞订单号
- 金额
- 完成天数
- Day8 状态
- 物流状态
- 断卡情况
- 审核状态
- 操作

操作：

- `审核通过`
- `拒绝`
- `查看依据`
- `查看用户`

### 9.3 审核依据

审核弹层展示：

- 是否完成 7 天。
- 是否完成 Day8。
- 是否订单已匹配。
- 是否物流已送达。
- 是否断卡超规则。
- 是否已有重复退款。

### 9.4 售后异常

异常类型：

- 物流异常
- 订单冲突
- 用户反馈不适
- 收货信息不一致
- 免单争议

## 10. 开发与发布 tab

### 10.1 页面目标

把当前开发校准内容保留给开发者和管理员，不占用运营首页。

### 10.2 页面结构

分组如下：

1. 上线闸口
2. 发布记录
3. Adapter 校准
4. 真实 Adapter 接入
5. 真实样本导入
6. Adapter 准入
7. 取样评审台账
8. 最近运行记录

### 10.3 命名规则

此 tab 可以保留开发词：

- Adapter
- Interface
- Implementation
- Seam
- 数据仓库 Adapter

其他运营 tab 避免出现这些词，改用运营可理解的表达。

`真实样本导入`说明：

- 用于开发/管理员校准平台字段、状态映射和 Adapter 准入。
- 与订单匹配 tab 的`批量粘贴订单`不同，不作为日常运营默认入口。
- 继续展示样本评审、字段覆盖、未知枚举映射和最近运行记录。

## 11. 关键状态文案

| 内部状态 | 运营展示 |
| --- | --- |
| `REGISTERED_IDLE` | 已注册，待匹配/待开始 |
| `CHECKIN_ACTIVE` | 打卡中 |
| `CHECKIN_COMPLETED` | 试饮记录完成 |
| `DAILY_USER` | 日常记录中 |
| `MANUAL_REVIEW_REQUIRED` | 需要人工确认 |
| `DELIVERED_NOT_STARTED` | 已送达，待开始 |
| `FULFILLMENT_EXCEPTION` | 物流异常 |
| `REFUND_PENDING` | 免单待审核 |

## 12. 交互状态

### 12.1 加载

- 页面首次加载展示骨架行。
- tab 切换保留已加载数据，点击刷新再拉取最新数据。

### 12.2 空状态

空状态文案应给出下一步：

- 无待办：`今天暂无待处理事项，可以查看用户记录或刷新数据。`
- 无订单：`暂无待匹配订单，可手动新建有赞订单。`
- 无异常反馈：`暂无异常反馈。`
- 无候选用户：`未找到可匹配用户，请换手机号搜索，或先让用户完成小程序登录。`
- 无候选订单：`未找到订单，可录入新订单或批量粘贴订单。`

### 12.3 错误状态

错误提示需要可操作：

- `订单号已存在，请检查是否要更新订单。`
- `该订单已绑定其他用户，请确认后再继续。`
- `手机号不一致，建议先核对收货信息。`
- `保存失败，请刷新后重试。`
- `用户已有活跃订单，请确认是否仍要匹配新订单。`
- `订单已绑定其他用户，默认不可直接覆盖；如确认改绑，请填写备注。`

## 13. 本轮不做

- 不做复杂权限系统。
- 不做多运营账号审计。
- 不做自动连接有赞开放平台配置页。
- 不做图表型 BI 大屏。
- 不改小程序端流程。
- 不迁移底层数据仓库 Adapter。

## 14. 评审检查清单

设计评审时重点检查：

- 运营者首屏是否能知道今天要处理什么。
- 开发内容是否已经从默认首页移出。
- 手动匹配订单是否足够防错。
- 用户详情是否能判断用户卡点。
- 免单审核是否能看到依据。
- ROOT 品牌感是否存在，但没有牺牲后台效率。

1. 今日运营指标与现有数据字段的对应关系。
