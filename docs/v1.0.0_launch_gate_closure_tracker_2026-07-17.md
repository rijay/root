## 1. 目标与裁决原则

本台账用于推进 PRD baseline、远端 CI、Candidate/生产基础设施、制品来源、平台权限、告警、密钥、微信送达以及内容/设计授权。它只记录已经读取的证据和下一步动作，不以模板、环境变量名、本地测试、历史候选或 UED 占位关闭真实 Gate。

统一状态：

- `CLOSED`：具名负责人、时间、不可变证据引用和验收结果齐全。
- `READY_FOR_SIGNOFF`：材料已齐，只差指定人员签署。
- `READY_FOR_AUTHORIZED_ACTION`：本地前置已齐，只差一次性高影响动作授权。
- `IN_PROGRESS`：存在可继续实施的本地工作。
- `OPEN / HARD BLOCKER`：缺少外部材料、真实环境或实现，不能关闭。
- `STALE_SNAPSHOT`：只有历史只读证据，不能代表当前状态。

复合状态的左侧描述主状态，右侧描述限定原因；只有精确单值 `CLOSED` 才代表 Gate 已关闭。`READY`、`IN_PROGRESS`、`PARTIAL`、`SELECTED`、`INVENTORIED` 或 `PENDING` 均不得解释为发布许可。

`OWNER_TBD`、空日期、未绑定固定授权语句和 source digest 的口头确认、截图占位、README 示例值、旧 releaseId 或没有 digest 的文件都不能产生 `CLOSED`。唯一例外是 2026-07-28 明确批准的新治理机制：`DIRECT_ACCOUNTABLE_OWNER_DIRECTIVE_V1` 必须通过 V2 Contract、固定授权语句摘要、source binding、完整风险覆盖和 fail-closed Validator 形成 Acceptance Envelope；它只允许关闭 PRD baseline 审批，不产生任何运行或发布授权。
