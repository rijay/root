# 0.8.7 登录冲突修复

日期：2026-09-05。修复并入已有 0.8.7 候选，不单独创建版本。

## 问题与行为

同一手机号的会员账号已绑定本应用其他微信身份时，服务端抛出 `WECHAT_APP_IDENTITY_AMBIGUOUS`。此前服务端冲突映射漏掉该错误码，客户端又用字符串同时包含 `IDENTITY` 与 `CONFLICT` 判断，最终错误地提示重新授权。

本次处理：

- 服务端补齐错误码映射；修正冲突响应缺少 `{ code, message, data }` 外层结构的问题，返回 `data.sessionOutcome = IDENTITY_CONFLICT` 和空 token。
- 客户端识别四种明确的绑定冲突错误码，兼容旧服务端的 409 返回及新服务端的结构化结果。
- 提示改为“账号绑定冲突”，明确重新授权无法解决，指引使用原绑定微信、联系客服核实或返回首页浏览。
- `identity.js` 绑定校验和数据规则未修改，不自动改绑、合并账号或签发冲突会话。普通临时失败仍提示重新获取一次性的手机号授权码。

## 验证

- 修复前已复现漏识别、错误提示及 API 响应格式失败；修复后登录相关定点检查 19 项通过。
- 新增真实回环 HTTP 回归：同一合成手机号先绑定原微信，再从另一微信登录，正式流程返回冲突；旧协议仍为 409。身份记录、会话和 token 映射均保持原样。
- 客户端回归运行实际登录页及请求模块，只替换 wx 平台接口：四种 409、结构化冲突、临时失败、成功登录及提示文案。冲突不自动重试、不创建会话、不跳转，保留登录后的目标页。
- 全量本地功能检查：backend 714 PASS / 5 SKIP、小程序 332 PASS、admin 41 PASS、tooling 28 PASS，共 1,115 PASS；构建与路由检查通过。
- 登录源码增加 204 bytes 后，包体证据按实际值刷新并单独复验通过。所需 7 个阶段均已验证；5 项默认 MySQL 跳过项由远端既有专项门禁继续覆盖。
- 微信模拟器展示冲突状态，文案清晰且未遮挡按钮。该项使用页面状态夹具，无真实手机号授权，不能替代真机登录验收。
