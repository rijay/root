## 1. 范围声明

0.7.0 只以本文五项需求为范围来源。此前主 checkout 中未提交的方案及其 PRD 不进入本版本，不从 0.6.1 归档分支、归档标签或 `main` 回收实现。

## 2. 版本目标

1. 以黑、白、品牌橄榄绿和中性灰重建统一视觉体系，移除界面中的米色主基调。
2. myRoot 展示 Root 会员商城的订单、优惠券和实时商品价格摘要，并保留可靠的跨小程序跳转。
3. 优化首屏资料和图片加载，消除“我的”页已登录用户先显示未登录或核验中的明显闪烁。
4. 将健康问卷草稿、评测结果和回测记录保存到服务端，支持用户逐条删除。
5. 用户完成健康起点评测和肠道健康 5 道题自测后，展示由已审核规则确定的当前状态，并提供安全受控、可降级的模型辅助健康建议。

## 3. 产品与实现要求

### 3.1 全局配色

- 单一品牌色源：黑、白、品牌橄榄绿、中性灰；警告和风险色只用于对应语义。
- 页面和组件使用语义 token，不再直接写旧米色值。
- 不做不区分语义的全局颜色替换；按首页、商品、健康、活动、我的及次级页逐页验收。
- 图片素材中的自然色不属于代码配色门禁，但页面底色、文字、边框、按钮和渐变属于门禁范围。

验收：

- 旧米色调色板不再出现在 WXML/WXSS；新增自动检查阻止回归。
- 五个 Tab、登录注册、健康全流程、活动详情、内容详情和个人设置均无文字不可读、按钮失色、遮挡或布局漂移。
- 开发者工具与至少一台 iOS、一台 Android 真机完成逐页截图比对。

### 3.2 商城数据与跳转

- Root 会员商城是订单、优惠券和商品价格的权威来源；myRoot 只做只读聚合展示，不自行判定支付、核销、库存或售后最终状态。
- 账号优先使用同一微信开放平台下的可信 UnionID 关联；缺失或冲突时不得按昵称自动合并。
- “我的”页展示订单摘要、可用优惠券数量和更新时间；商品页展示服务端返回的价格及同步时间。
- 订单、优惠券和商品均可跳转到对应商城目标；跳转失败保留当前页面、可重试，返回 myRoot 后恢复原页面状态。
- 外部接口不可用时显示“暂未同步/以会员商城为准”，不得用本地静态值冒充实时数据。

验收：

- 同一测试会员在商城与 myRoot 的订单、可用券和商品价格一致。
- 无 UnionID、身份冲突、空数据、超时、令牌过期和跨小程序跳转失败均有可理解的降级状态。
- 完成脱敏只读探针、分页读取到结束、去重和读后校验；未读取真实数据前不得宣称已打通。

### 3.3 加载体验

- 登录资料采用“本地最小快照立即展示、后台刷新”的方式；退出登录或会话失效时同步清除快照。
- 页面请求去重、可取消，保留现有并发和超时预算；刷新失败时保留上次可用内容并明确提示。
- 非首屏图片懒加载，固定占位尺寸并处理加载失败；首屏关键图片保留优先加载。
- 记录页面可用内容时间、资料刷新耗时和图片失败率，不记录头像、健康答案、订单或优惠券内容。

验收：

- 已登录用户二次进入“我的”时首帧直接显示缓存资料，不先闪成“未登录”。
- 资料刷新失败时仍显示缓存资料并提示可重试；退出后不得残留上一位用户资料。
- 非首屏图片启用懒加载，图片加载前后不造成主要布局跳动。

### 3.4 健康数据服务端保存与删除

- `INITIAL` 与 `GUT_REGULARITY` 的草稿、答案、结果、问卷版本和回测记录统一由服务端保存。
- 只允许当前登录用户读写自己的记录；所有写入继续受健康敏感信息单独同意控制。
- 历史页和结果页支持逐条删除。删除一个评测记录时，其答案、结果、维度和以该记录为输入的模型建议一并删除或失效。
- 删除操作幂等；成功后立即从用户界面消失。必要安全审计只记录操作事实和记录 ID，不保存被删健康内容。
- 保存期限、到期脱敏、撤回同意和用户主动删除是不同机制，分别验证。

验收：

- 同一用户换设备登录后能读取服务端历史；不同用户不可互相读取。
- 草稿中断后可恢复；相同问卷 ID 与版本的两次结果可对比。
- 用户删除后详情、历史和对比均不可再访问；重复删除不报未知结果。

### 3.5 当前状态与模型辅助建议

- 当前状态由版本化、已审核的问卷评分和安全规则确定，模型不得改写评测分类或安全分流。
- 仅在两项评测均完成后生成综合建议；模型只接收完成建议所需的最小结构化结果，不接收用户标识、联系方式或原始自由文本。
- 输出使用固定 JSON 结构，经字段、长度、禁用表达和安全规则校验后才能展示。
- 命中风险分支时不调用普通建议模型，只展示经专业审核的固定安全内容。
- 模型超时、限流、返回非法内容或服务未配置时，自动降级到经审核的固定建议，不阻断评测结果。
- 页面显著标注“AI 辅助生成”，保留模型、提示词、内容和规则版本，但普通日志不记录健康原文。

验收：

- 缺任一评测时明确提示还需完成哪一项；两项完成后展示两项当前状态和三条可执行建议。
- 风险样本不调用普通模型；模型故障时仍返回安全固定建议。
- 相同两次评测记录复用已生成建议，不因反复打开页面重复计费或产生漂移。
- 上线前完成专业内容审核、隐私影响评估、模型供应商与境内数据处理边界确认。
