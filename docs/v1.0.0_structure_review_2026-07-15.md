## 5. P0 产品结构与 UED handoff 阻断项

### SR-P0-01：成年资格缺少 Canonical 状态、事实归属和 Interface

D-009 已规定健康旅程只面向完成成年资格确认的会员，PRD 的健康入口与 AC-06 也依赖该判断；但 PRD 第 6.1 节状态轴、目标 Module 表和业务记录表均没有成年资格事实。

影响：多个页面只能各自推断资格，无法验证“不保存生日原值”、证据版本、有效期、原因与人工复核的一致性。

最小关闭条件：

- 指定唯一事实归属 Module；
- 冻结 `UNKNOWN / ELIGIBLE / INELIGIBLE / REVIEW_REQUIRED` 等 Canonical 状态或等价、已签署模型；
- Interface 只返回资格、原因码、证据版本、有效期和恢复动作；
- 增加记录、迁移、路由行为、AC 和 UED Frame 映射。

### SR-P0-02：次日提醒未进入 Canonical 模型

V1-9002 描述了次日打卡提醒场景，但状态轴、目标 Module、业务记录和 P0 AC 均未完整纳入提醒。Gate 决议却要求区分可申请、允许、拒绝、平台禁用、模板不可用、已排期、发送未知和送达验证。

影响：授权选择、一次性授权额度、提醒任务、发送结果和送达证明会被错误合并；“已允许”可能被误画成“已送达”。

最小关闭条件：

- 由 PRD 冻结唯一事实归属；优先沿用并升级现有 `checkinReminder` 为 `Check-in Reminder Module`，不在页面或报告中另造多个候选所有者；
- 冻结授权、额度、排期、发送与送达的正交状态；
- 定义幂等键、未知结果不重试规则、Interface、记录和 Adapter；
- 增加正常与异常 AC，并把 `206:23` 映射到任务页入口及完整结果页。

### SR-P0-03：Health Journey Module 的事实归属在 PRD 与 Design 中冲突

PRD 规定 Health Journey Module 只组合只读 Interface，健康同意、分类、评测、问卷与建议分别拥有事实；`design.md` 第 8.3 节却让 Health Journey Module 接收同意/拒绝/撤回、保存草稿、接收答案并返回结果。

影响：同一事实出现多个写入所有者，撤回并发、草稿清理、重新同意和结果失效无法获得 Locality。

最小关闭条件：`design.md` 中 Health Journey Module 只保留可重建投影和下一步展示 Interface；所有写操作指向 PRD 规定的事实归属 Module。

### SR-P0-04：任务到奖励路径绕过 Settlement Module

PRD 的链路是 `Task Module → Settlement Module → Reward Ledger Module`；`design.md` 的流程与 Interface 却让 Task Module 直接向 Reward Ledger Module 请求结算。

影响：任务完成、规则达标、奖励承诺和外部到账失去清晰事实归属；取消活动后的重算与补偿不可执行。

最小关闭条件：

- Task Module 只产生任务完成事实；
- Settlement Module 使用冻结规则版本产生达标或重算事实；
- Reward Ledger Module 只据达标事实创建和维护奖励承诺与交付状态；
- 同步流程图、Interface、事件、AC 与 UED 文案。

### SR-P0-05：M3 与 M5 存在不可完成的 Gate 循环

M3 退出要求 H-01～H-04 全部关闭；H-04R 只能在 D0 候选后取得；D0 又安排在 M5。

影响：按当前依赖顺序无法退出 M3，也就无法到达创建 D0 的 M5。

最小关闭条件：M3 调整为 H-01～H-03、H-04P 和健康写入关闭下的 Implementation 验证；D0 后在 M5/B1 关闭 H-04R，再进入 D1 健康 UAT。

### SR-P0-06：Canonical Route Registry 与 UED 页面形态未冻结

PRD 的部分健康路径仍称“建议分包”，`design.md` 的会员关联、分类、结果和建议仍标为“目标路由待定”；任务详情、成年资格、提醒和隐私请求状态也没有明确是独立路由、Modal、Sheet 还是页内状态。

同时，PRD 保留 `/pages/login/index` 与 `/pages/register/index`，UED 又提供统一 `AUTH-02`，未说明两条旧路径如何落到一个页面 Implementation。

最小关闭条件：分开建立两组登记，不能把 Overlay、Sheet 或页内 Variant 伪装成 Canonical 路由：

- Route Registry：`routeId / canonicalPath / ownerModule / access / parameterAllowlist / fallbackRouteId / legacyAdapter / AC`；
- UED 呈现登记：`screenId / presentationKind / owningRouteId / variantId / entry / backBehavior`。

并删除 `design.md` 的路由待定项，隔离旧 AUTH-01。

### SR-P0-07：缺少可审计的需求追踪闭环

PRD 有 V1、状态、Module、AC 和 Gate；Ardot 有画板；但不存在统一的：

`V1 条款 → Canonical 状态 → 页面/Frame → Interface → AC → Gate → 证据负责人`

追踪表。部分链路可以人工重建，例如活动报名可以回溯到 V1-5003、活动 Canonical 状态、Activity Module、AC-13～AC-15C 和 D-005；但当前无法证明 P0 覆盖率为 100%，语义相近也不能替代明确映射。

当前 AC 还缺少：

- 分类成功 → 评测提交 → 处理中 → 结果 → 建议的健康正常链路；
- 首套主题问卷的正常完成；
- 提醒授权、额度、排期、未知结果与送达验证；
- `DISABLED` 账号、`LOCKED` 任务和首页 Hero 发布/回退；
- Privacy Rights 的身份核验、影响确认、申诉等完整页面闭环。

最小关闭条件：先补齐缺失 AC，关闭 PRD baseline 的产品结构缺口；在 UED handoff/测试准备前建立 100% P0 追踪台账，不存在孤立需求、孤立 Frame、孤立 Interface 或无 AC 的写操作。

### SR-P0-08：UED 尚不是完整交互稿

以下 22 个 Conditional P0 Frame 仍是结构壳：

- 健康：`204:231/246/262/278/294/307/321/337/354`、`206:7/56/105`；
- 活动：`204:366/385/400/415`、`206:120`；
- 会员/任务/提醒/奖励：`206:40/75/89/23/134`。

五 Tab 也主要只有单一正常态，没有完整覆盖访客、已登录未关联、`ACTIVE / EXPIRED / SUSPENDED`、加载、真实业务空、网络失败、权限不足、数据过期和恢复。

微信平台隐私授权也没有与健康五态分开的完整条件流程；其触发、同意、拒绝、调用失败、恢复和本地 fallback 不能由健康同意页替代。

最小关闭条件：

1. 22 个 Frame 均有可评审主体，不再只有 Header/CTA。
2. Gate 决议第 6 节所有状态都有独立 Frame、Overlay 或明确 Variant。
3. 每个 P0 行动都有入口、成功目标、失败目标、返回/退出和安全 fallback。
4. 提供 Ardot 可读取原型连线，或提供等价且已签署的交互流转表。

## 7. P1 一致性与交付质量问题

1. **Home Next-step Interface 过窄。** PRD 按账号安全、健康、活动、任务等优先级计算；`design.md` 只读取会员和健康状态。
2. **会员关联后路径不一致。** `design.md` 默认进入健康；PRD 要求优先恢复活动、任务等 routeIntent，失效时再解释并安全 fallback。
3. **健康起点措辞仍可能暗示强制。** “注册后先评测”应统一为“用户主动开始健康旅程后，从分类与评测开始”。
4. **健康草稿 TTL 口径冲突。** `design.md` 的 24 小时只能作为非生产脱敏测试值；生产口径必须由 D-007 冻结。
5. **设计母版不一致。** `design.md` 写 `375×812`，PRD 和 Ardot 使用 `390×844`；应冻结一个母版，其他尺寸作为验证断点。
6. **事件仍不足以计算指标。** 需补触发时点、actor、去重键、窗口、排除规则和迟到事件处理。
7. **Health Content Evidence Package 缺唯一写入所有者。** 多个健康 Module 使用它，但目标 Module 表没有指定事实归属。
8. **D-001～D-010 台账不可直接签字。** 需增加状态、具名负责人、截止时间、决定日期和证据引用。
9. **当前一般法律文案与成年健康限制需形成明确分流决定。** v0.5.13 仍有“未满十四周岁经监护人同意可使用”的通用口径；它不能被解释为允许进入成人健康旅程。
