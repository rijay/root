# v0.6.0 小程序范围差异评审

日期：2026-08-20
基线：`origin/main` / 小程序 `0.5.25`
评审对象：此前上传的 `0.6.0` 体验版工作区

## 1. 执行结论

此前体验版不应作为 v0.6.0 的继续开发基线。它把历史分支和未提交工作区中的大范围页面重构一并打包，造成启动页、首页、健康、活动等页面超出 PRD 的改动范围。结论为：拒绝在该包上继续收敛，改为从线上同源的 `0.5.25` 重建精简候选。

## 2. 实际差异

- 相对 `origin/main`：247 个已跟踪文件变化，另有 53 个未跟踪文件。
- 小程序已跟踪差异约为 12,969 行新增、7,633 行删除。
- `app.js`、`app.json`、`app.wxss`、首页、健康、活动、登录、注册、个人中心均出现结构或样式级改写。
- 工作区同时出现订单、积分、任务、打卡、退款等不属于本次 PRD 的页面与路由。
- 原有正式发布、性能与路由约束测试被删除或改写，无法再证明与线上版本等价。

## 3. 关键问题

### P0：构建基线错误

此前体验版来源是包含长期累计改动的工作区，而不是线上 `0.5.25` 加本次 PRD 增量。其影响范围覆盖全局路由、导航、视觉变量和主要业务页面，属于版本替换而非需求迭代。

### P0：非需求页面发生视觉与交互回归

启动页、首页、活动页本应保留现有结构和主视觉。此前包对这些页面进行了结构性改写，无法用“色彩修正”解释，也不能通过局部回退可靠修复。

### P1：健康范围混入旧功能扩张

PRD 需要的是初始评测回测、历史对比和肠道规律自测；不包含打卡、任务、积分、订单、退款等体系。此前工作区将这些页面和基础设施同时带入，显著扩大验收和发布风险。

### P1：测试证据失真

如果沿用当前工作区，即使新增测试通过，也不能证明未改变线上页面。必须保留 `0.5.25` 的原始测试，并在其上增加 v0.6.0 定向测试。

## 4. 测试覆盖判断

精简候选必须同时满足：

1. `0.5.25` 原有验证脚本保持通过；
2. 新增五栏导航、产品定位、商品跳转、评测历史与回测定向测试；
3. 启动页 WXML/WXSS、活动页 WXML/WXSS 与基线保持字节级一致；
4. 首页只允许新增产品推广入口，不允许替换轮播或内容加载机制；
5. 不注册打卡、任务、订单、积分、退款路由。

## 5. 影响面

此前体验版影响面为全局级：应用入口、正式路由表、底部导航、全局色彩、首页、健康、活动、登录注册及个人中心。精简候选把影响面收敛到五栏导航、产品页、首页产品入口、健康评测入口与新增评测子页面。

## 6. 历史基线

微信后台正式版本为 `0.5.25`，仓库 `origin/main` 的版本号同为 `0.5.25`，因此选择它作为唯一可信 UI 与行为基线。此前本地开发分支包含跨版本累积内容，不能用于判断本次 PRD 的合理差异。

## 7. 修正建议

- 从 `origin/main` 导出干净候选，禁止从当前脏工作区复制主页面。
- 启动页保留现有图片、排版和交互结构；如落实每次展示，仅修改进入策略。
- 首页保留全屏轮播，只叠加一个明确的产品推广入口。
- 活动页及活动详情保持原文件，仅调整新增产品 Tab 后的索引。
- 健康页沿用原视觉语言，删除旧量表入口，新增初始评测、肠道自测、历史与对比入口。
- 产品页作为主要新增页面独立设计；购买仅跳转 Root 会员中心对应商品页。
- 在预览和差异清单确认前，不替换当前体验版。

## 8. 方法

本次采用基线差异评审：以 `origin/main` 为基准检查文件状态、行级统计、全局路由、导航、主要页面和测试套件；再按 PRD 逐条进行必要性归因。结论只依据实际仓库差异和已读取 PRD，不把历史工作区中的功能视为本次授权范围。

## 9. 修正结果

- 已从 `origin/main` 的 `0.5.25` 导出独立候选，未编辑原脏工作区，也未覆盖微信后台现有体验版。
- 启动页 WXML、WXSS、JSON 与 `0.5.25` 哈希一致；只取消历史“已看过即自动跳过”的代码判断。
- 活动列表、活动详情、我的活动的 WXML/WXSS 与 `0.5.25` 哈希一致；业务代码只调整五栏导航后的 Tab 索引。
- 登录、注册、个人中心的 WXML/WXSS 与 `0.5.25` 哈希一致；注册页继续使用同一页面内的头像选择和昵称填写。
- 首页保留原轮播、内容接口和主视觉，只增加产品推广 Banner 与“立即探索”。
- 健康页是唯一需要内容级调整的既有业务页面：去除旧量表入口，接入初始评测、肠道规律自测、历史、回测和同版对比。
- 未注册打卡、任务、订单、积分、优惠券、退款等越界路由。
- 完整 `npm run check` 通过，包含原回归、范围哈希、产品跳转、评测分支、历史对比、分享策略、性能和请求测试。
- 微信开发者工具 Preview 编译通过，总包 603.9 KB；主包 490.9 KB，健康分包 45.0 KB。

## 10. P0 评测存储闭环（2026-08-21）

- v0.6.0 正式包不再切换到尚未部署的 069～071 迁移及 `/api/v1/health/assessments/*` Interface。
- 初始评测、肠道规律自测、历史与同版回测在 develop、trial、release 三类包中均使用本机存储；正式环境的登录、内容、活动、商品跳转及埋点仍保留原正式配置，不启用全局兼容模式。
- 用户界面明确提示：记录只保存在当前设备，更换设备、清理小程序数据或卸载后可能无法恢复。
- 游客记录在完成手机号登录后归入稳定会员 ID；token 更新不影响同一会员读取，退出后游客与其他会员不会看到该会员记录。
- 跨设备同步与服务端健康档案不属于本次快速上线范围；后续只有在 069～071 和对应 API 完成独立部署、验证与数据迁移方案后，才能把 `healthAssessmentStorageMode` 切换为 `SERVER`。

## 11. P2 体验与异常退路收尾（2026-08-21）

- Banner、二维码或分享链接携带失效 `productId` 时，不再保留无效选中态；页面按“有效的原浏览商品 → 首个有效商品”的顺序回退，并显示“指定商品暂不可见”说明。
- 商品详情参数无效时提供“查看全部产品”和“返回首页”两个出口，不发起会员中心跳转。
- 产品横向 `scroll-view` 增加显式高度，修复微信模拟器中商品卡片区域被压缩为 0 的问题；提示条不再复用带 `100vh` 的 `.root-page`，避免把商品卡片推到首屏之外。
- 无效商品详情状态容器增加 `align-content: start`，防止两个退出按钮被 Grid 拉伸为大面积色块。
- 产品、健康评测历史/对比/结果及渠道异常页补齐加载、错误、筛选与选择状态的辅助技术语义；健康入口未开始状态由“未完成”改为“未开始”。
- 新增 `p2-polish.test.js` 并纳入完整 `npm run check`；本节不启用运营弹窗、渠道配置，不回填未知 `skuId`，也不替换商品真实素材。
