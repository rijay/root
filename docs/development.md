# myRoot 开发与验证流程

## 工作树与基线

1. 从已有仓库执行 `git worktree list --porcelain`，核对目录、分支、提交和 `git status --short`。Root 项目外层目录不一定是 Git 仓库。
2. 核对最新需求对应的工作树及小程序版本，不能仅凭目录名、`main` 或最后一个绿色 CI 选择基线。小程序和服务端可能位于不同分支，未提交修复应单独记录来源与哈希。
3. 使用 `git worktree add -b codex/<任务名> <新目录> <已核对的基线提交>` 创建任务工作树。复制既有修复前保存补丁与原工作区状态；本次改动使用独立提交，方便审查与恢复。
4. 在新工作树执行 `nvm use && npm run setup && npm run admin:build && npm run doctor`。各树独立安装依赖、构建并保存 SQLite，不共享可写数据或指向其他任务的 `node_modules` 软链接。
5. 完成后用 `git diff --check`、相应验证和日志核对结果。交接记录源提交、任务提交、工作区差异、已运行检查和未完成验收。
6. 推送、合并、部署前核对用户已授权的准确目标。远端 PR 为空只表示没有待审 PR，不表示本地变更已入库。未回读远端提交和 CI 时保留待验证状态。

## 调试入口

| 场景 | 命令或入口 | 可观察结果 |
| --- | --- | --- |
| 环境与基线 | `npm run doctor` | 目录、提交、依赖、小程序版本、本地构建 |
| 纯本地联调 | `npm run dev:local` | SQLite 路径、回环 URL；不读取云凭据 |
| 后台热更新 | `npm run dev:admin` | 5177 端口；API 代理到 8787 |
| 小程序模拟器 | 导入当前树 `miniprogram/` | develop/devtools 走 8787；网络面板可核对 |
| Node 调试器 | `node --inspect=127.0.0.1:9229 scripts/dev-local.js` | 本机调试器可在 API/Store 内断点 |
| 服务探针 | `curl -fsS http://127.0.0.1:8787/health` 和 `/ready` | 检查 JSON 的 code、服务与 Store 状态 |
| 端口冲突 | `lsof -nP -iTCP:8787 -sTCP:LISTEN` | 确认占用者，避免误连旧树或误杀服务 |

同时调试多棵树时，本地服务可用 `npm run dev:local -- --port=8788`。当前小程序模拟器和 Vite 代理固定连接 8787，因此换端口用于独立 HTTP 调试；切换模拟器前先核对并有序停止自己启动的旧服务。自动 QA 始终使用随机端口，不争抢 8787。

`backend` 中的 `dev:miniprogram` 保留旧 Keychain 有赞联调入口，仅在明确需要、具备该范围授权时使用。日常开发使用根目录 `dev:local`。

## 验证循环

1. 先复现：记录命令、输入、期望、实际、工作树与提交；能使用合成数据就不读生产数据。
2. 按修改范围运行 `npm run verify -- --only=...`。API 和持久化变更运行后端及 `qa:local`；页面/请求层运行小程序；后台运行 admin 和 build；流程脚本运行 tooling。
3. 全量 `npm run verify` 将每阶段日志和测试通过/失败/跳过数留下来。单阶段失败不会掩盖其他阶段结果；用户取消则停止后续阶段。
4. 证据快照差异应核对实际源码/构建变化。只在确认后执行 `evidence:local:write`；禁止为了变绿删除检查、放宽体积预算或把缺失设备样本改为通过。
5. 所需检查通过后结束本轮，不重复重跑未改变的阶段。MySQL 分支跳过时写出缺口；SQLite 无法证明 MySQL 事务、迁移和多实例行为。

## QA 层次与验收表

| 层次 | 当前可执行证据 | 适用边界 |
| --- | --- | --- |
| 小程序自动回归 | 请求/缓存/渠道生命周期/授权等 `scripts/*.test.js` | Node 与微信 API stub；无真实渲染证明 |
| 本地跨层联调 | `npm run qa:local` | 真实小程序 Module + HTTP + SQLite，wx 传输替换；合成用户 |
| 后台渲染 | 本地构建后进入 `/admin/`，检查用户标签、渠道、测评管理 | 记录浏览器、页面、网络请求、截图和合成数据范围 |
| 真实 MySQL | CI 的一次性 marker 数据库、schema/migration/integration 阶段 | 不能用 localhost 字样替代隔离数据库证明 |
| 微信工具与真机 | 对绑定提交的体验包逐项操作下表 | 记录实际设备、版本、进入路径与结果 |

设备 QA 最小表（每行填写通过/失败/未测，附版本及证据）：

- 冷启动扫码、已运行后扫码、换码进入、旧无 q 码：核对目标页和唯一一次访问记录。
- 首次授权、拒绝、撤回、再次授权：核对拦截和结果可见范围。
- 普通题切换、快速连续切题、断网重试、安全题停止、提交重试：核对草稿与结果，不重复完成。
- 活动首屏、图片、我的缓存、退出后换账号：核对缓存隔离、失效和加载状态。
- 产品/会员商城跳转与返回：记录实际身份与线上数据能力，不能从本地模拟推断接通。
- iOS 顶部回弹、题间回顶；Android 显示、弱网与恢复：记录设备观察。

需要性能验收时绑定包/提交/网络条件，按现有性能预算采集足够样本并看 P75/P95、帧率和内存。合成查询基准只支持对应算法改进的判断。

## 接续停滞工作

先用任务状态和最近输出判断：正在计算、等待外部权限、等待设备确认、命令卡住和代码循环需要不同处理。保持原任务与原工作区；把复现输入、第一次失败、已尝试手段和剩余条件带到独立工作树。同一错误重复出现而无新证据时，查看完整阶段日志并改变验证方式。遇到进程挂起使用阶段超时或取消；不通过反复启动同一命令制造多个服务。只有完成实际复现与回读，才能把接续工作标为解决。
