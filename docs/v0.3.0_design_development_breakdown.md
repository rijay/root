## 1. Finish Line

V0.3.0 完成后，用户在 7 天试饮期仍能清楚完成打卡、问卷、复购礼和免单路径；完成 7 天并继续记录后，小程序主体验切换为“日常身体记录”，并在每日记录后支持生成分享图。

本轮拆单必须确保：

- `DAILY_USER` 不再被全局 7 天叙事包裹。
- 打卡成功后进入结果页，而不是直接回首页。
- 分享图主路径是保存到相册。
- 用户可见日期统一为中文自然日期。
- 身体反馈画像只展示参与原因、肠道状态、改善方式。

## 2. 当前落点摘要

现有可复用能力：

- 日常用户状态已存在：`DAILY_USER`。
- 日常统计已存在：`/api/v1/daily/stats` 对应 `dailyStats`。
- 日常历史已存在：`/api/v1/daily/history` 对应 `dailyHistory`。
- 事件记录已存在：`/api/v1/event/track` 对应 `trackEvent`。
- 图片上传与本地媒体选择已有基础路径。

当前主要缺口：

- `subpkg/checkin/pages/today/index` 成功后仍 toast + 回首页，没有稳定结果页承接。
- `subpkg/checkin/pages/result/index` 只支撑 7 天试饮周期，不能展示日常记录结果。
- `pages/home/index`、`pages/profile/index`、历史页仍有 7 天表达残留。
- 日期展示直接使用内部日期文本。
- 身体反馈画像直接展示枚举值，并包含日常便型。
- 分享图生成、预览、保存路径尚不存在。

## 3. 设计拆单

### DES-3001 日常首页状态卡

优先级：P0

目标：

- 为 `DAILY_USER` 设计独立首页状态，不使用深色 7 天试饮卡。

设计内容：

- 浅色日常状态卡。
- 标题：`今日身体记录`。
- 统计：累计记录、当前连续、最长连续。
- 主行动：`记录今天` / `查看今日记录`。
- 次级入口：记录历史、复购、免单状态。

验收：

- 不出现 `N/7`、`Day N / 7`、`7 天数据总结`。
- 首屏只有一个主行动。
- 统计卡在小屏幕下不拥挤、不换行穿插。

### DES-3002 完成态首页状态

优先级：P0

目标：

- 处理 `CHECKIN_COMPLETED` 到 `DAILY_USER` 的过渡体验。

设计内容：

- Day8 未完成：主卡强调收尾问卷。
- Day8 已完成：主卡强调试饮记录已完成，主行动为继续日常记录。
- 免单状态作为次级信息。

验收：

- 完成 7 天后不会立即把“申请免单”变成唯一主任务。
- 继续日常记录入口足够明确。

### DES-3101 今日打卡页阶段化表单

优先级：P0

目标：

- 同一打卡页支持试饮期和日常期两套顶部表达。

设计内容：

- 顶部阶段卡。
- 两个必填二选一区。
- 便型按条件展开。
- 身体感受输入与中性快捷短句。
- 图片上传次级入口。
- 底部固定保存按钮与缺失提示。

验收：

- 日常态标题不出现“第 N 天”。
- `昨日是否排便` 必须有 `有 / 没有` 二选一控件。
- 选择 `有` 时展示便型选择；选择 `没有` 时隐藏便型选择。
- 未选必填项时，用户知道缺哪一项。
- 便型选中态不只依赖颜色。

### DES-3201 结果页双模式

优先级：P0

目标：

- 结果页同时支持试饮期记录结果和日常记录结果。

设计内容：

- 试饮期：阶段进度、下一步、分享图入口。
- 日常期：今日摘要、累计/连续统计、分享图入口。
- 人工协助态：不展示分享图主入口。

验收：

- 普通成功提交后能进入结果页。
- Day4/Day8 问卷优先级高于分享图。
- 复购礼不抢结果页主按钮。

### DES-3301 分享图模板

优先级：P0

目标：

- 设计一张可保存、可转发、适合朋友圈和小红书的个人记录图。

验收：

- 添加中性快捷短句，点击后填入反馈框。

- 日常态不出现“第 N 天”。

建议测试：

- `hadStool = null`：保存按钮提示 `请选择昨日是否排便`。
- `hadStool = true` 且未选便型：提示 `请选择昨日便型`。

- `hadStool = true` 且已选便型：提交摘要和结果页展示便型。

## 5. 批次顺序

建议开发顺序：

1. Batch 0：基线与扫描。
2. Batch 1：Date Display 与选项中文展示。
3. Batch 2：首页和我的页阶段叙事。
4. Batch 3：今日打卡页与结果页。
5. Batch 4：分享图 Module 与预览页。
6. Batch 5：历史与画像收口。
7. Batch 6：全量回归。

原因：

- 日期和选项展示是底层表现能力，应先做。
- 阶段叙事先进入首页，用户主路径先清楚。
- 结果页必须先于分享图，否则分享图没有稳定入口。
- 历史与画像可以跟随收口，不阻塞主路径联调。
