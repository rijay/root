## 4. 团队 P0 测试路径

1. 扫体验版二维码，确认能打开 myRoot 首页。
2. 勾选协议后点击 `微信身份进入`，确认不再触发强制手机号授权。
3. 进入商品 tab，确认能看到 `ROOT益生元 7天身体重启计划`。
4. 点击商品详情，确认商品名称、价格、说明和按钮文案正常。
5. 点击去购买，确认跳转到微信小程序 `Root会员中心`，路径为 Root 会员中心商品详情页；不要完成真实付款。
6. 返回 myRoot，进入任务 tab，确认打卡任务入口可见。
7. 点击加入打卡活动；若已配置打卡提醒模板，确认出现微信原生订阅消息弹层，接受或拒绝后都不阻断后续流程。
8. 进入打卡或问卷路径，完成一次测试提交，确认没有白屏、死循环或错误 toast。
9. 进入奖励 tab，确认结算状态、奖励说明和未达成提示能正常展示。
10. 进入个人或订单相关入口，确认未绑定订单时不会阻塞使用。
11. 进入咨询/客服入口，确认能看到用户咨询或人工协助入口。

## 6. 已知限制

1. 当前内测 Store Module Adapter 是 SQLite，且文件在容器 `/tmp`；容器重启或扩缩容可能导致测试数据丢失。
2. 当前内测后台已配置 `ROOT_ADMIN_TOKEN`，后台写操作需携带 token；正式上线仍需按角色拆分 viewer/finance/operator/admin 等口令或账号策略。
3. 有赞订单、有赞客户、物流、企业微信线索、发券和券状态等外部 Adapter 仍未接入真实小批量校准。
4. 内测商品快照由环境变量启动种子写入 Root 会员中心商品路径，不等同于有赞商品自动同步已完成。
5. 微信开发者工具里的页面 UI 仍需体验版真机复测；后端 Interface 和小程序 `wx.cloud.callContainer` 已验证通过。
6. 微信云开发内测环境出现过亚秒级硬突发 `EXCEED_RATELIMIT`，团队测试应按自然错峰节奏执行；正式上线前如要承接路演集中扫码，需要确认 CloudBase 套餐、实例数、并发和限流策略。
7. 本轮不测试真实支付、真实退款、真实优惠券发放和真实企业微信标签写入。
8. 打卡提醒订阅消息模板 ID 已取得，内测云托管环境已可读到模板配置；团队仍需用真机确认加入活动后的微信原生订阅授权弹层、接受/拒绝结果和次日提醒 Job dry-run。

## 9. 内测反馈与新需求归档规则

团队试用期间，所有反馈先按两类归档，避免把正式发布 Gate 和体验增强混在一起：

1. 缺陷：已实现路径不符合预期、报错、白屏、数据异常、跳转失败、订阅弹层异常或后台写入失败。
2. 新需求：当前范围之外的页面、运营规则、数据字段、提醒方式、活动玩法、商品展示或后台效率诉求。

优先级定义：

| 优先级 | 定义 | 处理方式 |
| --- | --- | --- |
| P0 | 无法登录、无法进入首页、商品跳转不可用、打卡/问卷主链路阻断、奖励状态严重误导 | 内测前或当天修复，必要时重新上传体验版 |
| P1 | 主链路可继续但影响团队判断，如弱网恢复差、重复点击异常、订阅授权记录异常 | 纳入下一轮体验版修复 |
| P2 | 文案、样式、引导、后台效率或非主链路体验问题 | 归入重构后续迭代 |
| P3 | 想法型增强或运营长期优化 | 进入需求池，等内测复盘统一排期 |
