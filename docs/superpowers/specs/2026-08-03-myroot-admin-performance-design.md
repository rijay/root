## 1. 文件效力与管理结论

本文件把运营后台性能从一般开发建议转为候选版本的构建、查询和浏览器准入条件。首发采用“轻量正式上线档”：满足 2 名核心运营稳定使用，并用最多 5 个同时在线会话验证简单余量，不为理论上的大团队和海量数据提前建设基础设施。

本阶段只有三层性能 Gate：

1. 构建 Gate；
2. 查询 Gate；
3. 浏览器 Gate。

本阶段不设置运营 Gate，不要求运营人员签署或完成阻断式性能验收。运营人员可以试用并反馈，但不形成独立 Gate。

本文件不证明现有后台已经达到指标，也不代表后台已经部署、生产数据已经迁移、小程序已经上传微信或产品已经正式发布。

## 2. 当前证据、缺口与处理原则

### 2.1 已读取的当前证据

- 后台使用 Vue 3、Vite 6 与 Element Plus；
- 当前 `admin/src/main.js` 全量注册 Element Plus；
- 当前 `admin/src/App.vue` 同步导入全部旧业务页面；
- 当前只读构建产物共 `1,635,246 bytes`，gzip 后各文件合计 `443,222 bytes`；
- 旧构建仍包含即将删除的配置、用户生命周期、Adapter 运行、运营分析和旧发布页面；
- 当前 Admin Request Module 默认 15 秒超时，能够区分读取失败与写入结果未知；
- 正式上线后台已经批准为发布、内容、活动、健康、用户与审计五组导航。

当前构建产物没有在本轮重新构建，可能落后于源代码，只作为规模参照，不作为候选版本基线或通过证据。

### 2.2 尚缺材料

- 两名运营实际使用电脑及浏览器数据；
- 真实生产用户、报名、审计和内容数据规模；
- 正式环境后台路由 P75/P95；
- 正式静态资源压缩与缓存响应头；
- 真实办公网络条件。

这些缺口不阻断设计，但必须在候选版本中实测。旧页面、旧查询和旧构建不得因为“已经存在”而获得保留资格，也不投入性能解耦或专项优化。

## 3. 使用规模与验收环境

### 3.1 使用规模

- 日常核心用户：2 名运营人员；
- 简单余量：最多 5 个同时在线会话；
- 同时读取请求验收上限：10 个；
- 不按 20–50 人并发设计；
- 不建设实时协同编辑、分布式查询或高并发缓存体系。

### 3.2 浏览器与设备

- 当前稳定版 Chrome；Edge 不在首发支持与性能验收范围内；
- 基准办公电脑不低于 4 核 CPU、8GB 内存；
- 高保真主验收内容区：`1240 × 820`；
- 每次报告记录电脑型号、系统、浏览器版本、视口和网络条件。

### 3.3 网络档位

- 标准办公网络：往返延迟约 80ms，下行 10Mbps、上行 5Mbps；
- 弱网：往返延迟约 200ms，下行 2Mbps、上行 1Mbps、丢包率 1%；
- 离线：无可用网络；
- 每个关键性能场景执行 20 次，以 P75 为主要结论，同时记录 P95。

网络参数用于形成可重复条件，不代表所有真实办公网络。

### 3.4 计时口径

- 首次打开：从浏览器开始导航，到身份结果、后台外壳和可用导航完成显示；
- 已缓存重新打开：相同起止点，但静态资源已有有效缓存；
- 菜单切换：从点击菜单，到目标页面主要表格或表单可以操作；
- 读取：从运营触发查询，到响应校验完成并渲染当前结果；
- 写入：从点击确认，到页面显示经过校验的权威结果；
- 异步页面：从第一次点击菜单，到异步代码、必要数据和主要操作区可用；
- 本文件时延目标适用于标准办公网络；弱网用于验证等待、超时和恢复，不要求达到标准网络时延；
- 浏览器内存按单个后台标签页测量，排除开发者工具和其他网站标签页。

## 4. 总体性能目标

| 场景 | 目标值 | 硬上限 |
| --- | ---: | ---: |
| 首次打开并显示可操作后台外壳 | P75 ≤ 2.5 秒 | 4 秒 |
| 已缓存后重新打开 | P75 ≤ 1.2 秒 | 2 秒 |
| 已加载菜单切换 | ≤ 300ms | 500ms |
| 首次打开异步业务页面 | ≤ 1 秒 | 1.5 秒 |
| 点击、筛选和翻页反馈 | ≤ 100ms | 200ms |
| 普通列表查询 | P75 ≤ 800ms | P95 ≤ 1.5 秒 |
| 单条详情读取 | P75 ≤ 600ms | P95 ≤ 1.2 秒 |
| 保存、发布和状态修改 | P75 ≤ 1 秒 | P95 ≤ 2 秒 |
| 表格和长表单滚动 | P75 ≥ 50 FPS | 不持续冻结超过 200ms |

性能优化不得删除或弱化已经批准的后台对齐、表格结构、状态标签、发布二次确认、错误提示、结果未知恢复、手机号脱敏或健康数据最小化要求。

## 5. Module 结构与加载方式

### 5.1 Admin Shell Module

`Admin Shell Module` 的 Interface 只负责：

- 后台身份状态；
- Root 文字字标；
- 侧栏与页头；
- 当前导航；
- 页面加载、错误和重试状态；
- 全局写入结果未知提示。

它不得同步包含所有业务页面的 Implementation。

### 5.2 业务页面 Module

发布、内容、活动、健康、用户和审计分别形成按菜单加载的页面 Module。每个页面 Module 只在第一次打开时加载；离开后卸载其大表格、图片预览和编辑控件，不同时保留全部 12 个后台页面。

不为了性能额外引入第二套路由框架或全局状态框架。是否沿用当前导航状态或使用已有路由能力由实施决定，但必须满足动态加载和可恢复导航 Interface。

### 5.3 Admin Request Module

所有页面复用一个 `Admin Request Module`，其 Interface 统一处理：

- 后台身份凭证；
- 超时与取消；
- 相同读取合并；
- 响应结构校验；
- 读取失败；
- 写入幂等；
- 写入结果未知；
- 请求编号和权威状态复读。

当前只有一个浏览器请求 Implementation，不为假设中的第二种请求方式建立 Adapter Seam。

## 6. 构建与传输预算

所有体积使用 `1KB = 1,024 bytes`、`1MB = 1,024KB`。压缩体积以候选环境浏览器实际传输的 gzip 或 Brotli 结果为准。

首屏全部静态资源包括 HTML、JS、CSS、Logo、图标和字体；单个业务页面异步代码使用压缩后的独立页面代码及其首次专用依赖计算。

| 项目 | 目标值 | 硬上限 |
| --- | ---: | ---: |
| 首次加载 JS 与 CSS 压缩体积 | ≤ 420KB | 520KB |
| 首屏全部静态资源传输量 | ≤ 500KB | 650KB |
| 单个业务页面异步代码 | ≤ 120KB | 180KB |
| 后台全部代码压缩体积 | ≤ 800KB | 1MB |
| 单次版本首屏体积增长 | ≤ 30KB | 超过 60KB 重新批准 |

实施要求：

- 后台外壳、身份、导航和统一错误状态进入首屏；
- 每个业务页面使用动态导入；
- 只引入首发页面实际使用的 Element Plus 能力，不再全量注册整个控件库；
- 不增加图表库、富文本编辑器、全局状态框架或第二套图标库；
- JS、CSS 使用内容哈希和长期缓存；HTML 不使用长期强缓存；
- 候选和正式传输支持 gzip 或 Brotli；
- 正式环境不发布源码映射文件；
- 构建报告必须列出首屏、异步页面和总构建体积。

## 7. 页面渲染与浏览器资源预算

### 7.1 DOM 与表格

- 首屏 DOM 节点目标 ≤ 1,200，硬上限 1,800；
- 单个完整页面目标 ≤ 2,500，硬上限 3,500；
- 表格默认 20 条，允许切换至 50 条；
- 不提供“一次展示全部”；
- 所有业务列表由后端分页；
- 首发不建设虚拟滚动；
- 筛选输入使用 300ms 防抖；
- 筛选或页面变化时取消失效请求；
- 新请求产生后，旧响应不得覆盖新页面。

### 7.2 响应式状态与主线程

- 页面只保存当前编辑和显示所需字段；
- 完整历史记录和未显示响应不得进入响应式状态；
- 单个同步主线程任务不超过 50ms；
- 不允许持续超过 200ms 的浏览器冻结；
- 大型 JSON 格式化、图片压缩和导出生成不得在浏览器主线程同步执行；
- 不使用自动轮询；运营主动刷新，或关键写入后读取权威状态。

### 7.3 浏览器内存

| 场景 | 要求 |
| --- | --- |
| 稳定工作内存 | 目标 ≤ 200MB，硬上限 300MB |
| 连续切换主要菜单 10 轮 | 内存增长 ≤ 20%，不得线性增长 |
| 连续编辑并关闭内容 10 次 | 回落到初始稳定值的 20% 范围内 |
| 连续使用 30 分钟 | 无崩溃、持续冻结或持续内存增长 |
| 表格与表单滚动 | P75 ≥ 50 FPS |

页面卸载时清理计时器、观察器、对象 URL、失效请求和大图引用。

## 8. 查询、响应与容量预算

### 8.1 后台读取与写入

| 类型 | P75 | P95 | 压缩响应体上限 |
| --- | ---: | ---: | ---: |
| 后台身份与基础导航 | ≤ 400ms | ≤ 1 秒 | 30KB |
| 发布工作台总览 | ≤ 800ms | ≤ 1.5 秒 | 100KB |
| 普通列表查询 | ≤ 800ms | ≤ 1.5 秒 | 100KB |
| 单条详情或编辑数据 | ≤ 600ms | ≤ 1.2 秒 | 200KB |
| 操作审计查询 | ≤ 1 秒 | ≤ 2 秒 | 150KB |
| 保存草稿和状态修改 | ≤ 1 秒 | ≤ 2 秒 | 50KB |
| 内容发布和活动状态操作 | ≤ 1 秒 | ≤ 2 秒 | 50KB |

列表只返回当前表格字段，详情在运营打开时单独读取。后台不得把会员资产、健康原始答案或无关历史版本放进列表响应。

### 8.2 分页与查询

- 所有列表默认 20 条、最大 50 条；
- 使用一套页码分页，不同时建设游标和页码两套 Interface；
- 用户查询优先使用手机号精确查询或明确筛选，不提供空条件全库模糊搜索；
- 活动报名、用户和审计查询必须有对应筛选和排序索引；
- 列表关联状态批量返回，不执行逐行查询；
- 总数只有界面确实展示时才计算；
- 不依赖 Redis 或独立应用缓存达到预算；
- 数据库连接配置沿用正式运行基线，不为 2 人场景扩大连接池。

### 8.3 性能验收数据量

- 用户：10,000 条；
- 活动报名：5,000 条；
- 操作审计：20,000 条；
- 内容版本：1,000 条；
- 量表编辑：100 题测试版本。

超过该规模后根据真实增长重新测量，不提前建设分布式查询。

## 9. 请求、写入与两人冲突

### 9.1 请求规则

- 同一浏览器最多 4 个并行读取；
- 相同查询合并；
- 页面离开时取消失效读取；
- 读取 8 秒后明确失败；
- 写入 15 秒后进入“结果待确认”；
- 读取失败由运营主动重试，不无限自动重试；
- 写入不自动重放；
- 点击写入后立即锁定当前按钮；
- 写入携带幂等标识；
- 完成或超时后读取权威状态。

### 9.2 两人同时编辑

本阶段不建设实时协同编辑和记录锁定系统。草稿携带版本号；两人同时修改时，后提交者发现版本变化后停止覆盖，显示“内容已被更新，请刷新后重新编辑”。

发布、取消发布和活动状态修改一次只改变一个权威状态。任何超时都不得自动显示成功。

### 9.3 简单容量

- 5 个登录会话同时使用；
- 最多 10 个并发读取；
- 两个测试会话同时编辑同一草稿；
- 两个测试会话同时发布同一内容；
- 连续筛选、翻页和刷新 20 轮；
- 不执行 50 人压力测试；
- 使用可重复脚本和候选环境验证，不引入专用压测平台。

## 10. 各运营页面性能预算

| 页面 | 主要性能要求 |
| --- | --- |
| 发布工作台 | 总览 P75 ≤ 800ms；各状态批量返回；不自动轮询 |
| 欢迎页 / 首页轮播 | 列表 P75 ≤ 800ms；编辑 ≤ 600ms；排序反馈 ≤ 100ms |
| 共用详情编辑 | 页面 ≤ 1 秒；热点拖动反馈 ≤ 100ms；只加载当前编辑图片 |
| 活动管理 | 列表 P75 ≤ 800ms；详情 ≤ 600ms；保存 P75 ≤ 1 秒 |
| 报名记录 | 筛选和翻页 P75 ≤ 800ms；报名状态批量返回 |
| 初始化建档 | 12 问版本完整打开 ≤ 1 秒；题目排序反馈 ≤ 100ms |
| 量表管理 | 列表 P75 ≤ 800ms；100 题样本编辑保持流畅 |
| 推荐规则 | 列表与匹配结果 P75 ≤ 800ms；保存 P75 ≤ 1 秒 |
| 生活方式建议 | 建议列表 P75 ≤ 800ms；不等待模型现场生成 |
| 用户查询 | 手机号精确查询 P75 ≤ 600ms；不支持空条件全量查询 |
| 操作审计 | 查询 P75 ≤ 1 秒；只读分页 |
| 发布确认 | 点击 ≤ 100ms 反馈；超过 2 秒显示明确进度 |

## 11. 素材、长表单与导出

### 11.1 素材上传

- 上传前在浏览器检查格式、尺寸和体积；
- 欢迎图、轮播图、活动封面和详情图片沿用小程序性能规格的硬上限；
- 列表只加载缩略图；
- 图片预览只加载当前素材；
- 不在浏览器主线程压缩大图；
- 合格素材在标准网络下上传并取得确认目标 ≤ 3 秒；
- 上传显示进度，失败只重试当前文件；
- 图片上传成功与内容发布成功是两个状态；
- 小程序预览生成目标 ≤ 1.5 秒，失败时保留草稿。

### 11.2 量表与长表单

- 初始化 12 问可以一次展示；
- 量表使用 100 题作为性能验收样本，不作为永久产品上限；
- 长量表按题组或每 20 题分段；
- 未展开题组不创建完整编辑控件；
- 修改当前题不得重新渲染整份量表；
- 不做持续自动保存，运营主动保存草稿；
- 离开存在未保存修改的页面前必须确认；
- 计分预览和完整校验由后端完成。

### 11.3 报名记录导出

- 单次导出最多 5,000 条；
- 超过 5,000 条时要求增加活动或日期筛选；
- 导出准备目标 ≤ 10 秒；
- 导出期间另一名运营的普通查询仍需满足查询 P95，不得阻塞后台主进程；
- 不建设大规模异步导出中心；
- 导出失败不得生成空文件或标记成功；
- 手机号脱敏和导出审计不因性能要求降低。

## 12. 弱网、身份失效与错误恢复

- 页面超过 300ms 未返回时显示稳定骨架或加载状态；
- 异步页面代码加载失败时保留后台外壳并提供“重新加载当前页面”；
- 筛选失败时保留筛选条件和当前表格；
- 写入超时显示“结果待确认”，读取权威记录后再允许重试；
- 身份失效时保留当前内存中的未保存表单，重新验证后继续；
- 不把后台草稿、Token 或健康配置长期存入本地存储；
- 上传失败保留其他已填写内容；
- 断网恢复后由运营主动刷新，不建设自动同步队列；
- 错误恢复不得放松脱敏、内容校验、健康安全或发布确认。

## 13. 轻量性能监测

不引入第三方性能平台。使用：

- Vite 构建体积报告；
- 浏览器首次打开、页面切换、内存和长任务数据；
- 后端结构化技术日志中的路由、耗时、状态码、响应体积和请求编号；
- 写入成功、失败和结果待确认记录。

日志不得记录后台 Token、手机号原值、图片内容、健康配置正文、健康原始答案或模型密钥。不建设实时性能大屏和运营性能看板。

## 14. 三层性能 Gate

| Gate | 验收内容 | 不通过处理 |
| --- | --- | --- |
| 构建 Gate | 首屏、异步页面、总构建体积、压缩与缓存 | 超过硬上限不得进入候选版本 |
| 查询 Gate | 分页、索引、响应体、P75/P95 和 5 会话余量 | 慢查询、全表读取或错误状态必须修复 |
| 浏览器 Gate | Chrome 首屏、切页、表格、表单、弱网和内存 | 卡顿、持续增长或操作无法恢复不得通过 |

不设置运营 Gate，不要求运营负责人签署或完成阻断式验收。性能错误导致的数据覆盖、重复发布、错误成功或状态无法恢复，由查询 Gate 或浏览器 Gate 直接阻断。

## 15. 候选版本验收旅程

由开发和测试执行：

1. 打开后台并完成身份验证；
2. 创建和保存首页轮播草稿；
3. 上传素材并生成小程序预览；
4. 两个测试会话同时修改同一草稿；
5. 发布一个内容版本并读取权威状态；
6. 创建活动并查询报名记录；
7. 导出筛选后的报名记录；
8. 编辑初始化 12 问和 100 题测试量表；
9. 配置推荐规则和固定生活方式建议；
10. 使用手机号精确查询用户；
11. 查询操作审计；
12. 在弱网、断网和身份失效后恢复操作。

关键页面场景各执行 20 次。运营人员试用和反馈为非阻断参考，不构成独立验收条件。

## 16. 回归、上线观察与阻断

### 16.1 回归规则

- 超过任何硬上限：阻断候选版本；
- 相比最近批准基线退化 5% 以上：预警并说明；
- 退化 10% 以上：即使未超过绝对上限也阻断；
- 首屏压缩体积增长超过 30KB：预警；
- 增长超过 60KB：说明原因并重新批准；
- 性能例外必须写明原因、页面、负责人和失效版本；
- 不允许以“只有两个人使用”为理由接受数据错误、重复发布或结果不明。

### 16.2 前 72 小时观察

正式上线需要单独批准。本文件不授权部署或上线。启用后的前 72 小时观察：

- 页面代码加载失败；
- 同一路由连续 3 次技术失败；
- 查询明显超过预算；
- 写入结果待确认；
- 内容、活动或健康配置与权威状态不一致；
- 运营反馈的持续卡顿或无法完成操作。

样本不足 20 次时不使用百分比下结论，直接查看失败次数和请求证据。任何错误发布、数据覆盖或健康配置错配都立即停止继续使用相关写入能力并核验权威状态。

## 17. 候选版本交付物

- Vite 构建与实际传输体积报告；
- 关键页面 20 次 P75/P95 报告；
- 后端查询计划、耗时和响应体报告；
- 5 会话余量和两个测试会话编辑冲突结果；
- Chrome、弱网和 30 分钟内存结果；
- 高保真一致性确认；
- 未通过项和临时例外清单。

交付物由开发和测试完成，不需要运营负责人签署。

## 18. 明确不做

- 不为 50 人以上并发做压力测试；
- 不引入 Redis 或分布式缓存；
- 不建设 WebSocket 实时同步；
- 不建设实时性能大屏或第三方性能平台；
- 不建设大规模异步导出中心；
- 不建设虚拟滚动和百万级数据浏览；
- 不引入图表库、富文本编辑器或新的全局状态框架；
- 不对即将删除的旧后台页面做性能重构；
- 不设置运营 Gate；
- 不把候选版本通过等同于部署、上线或线上稳定。
