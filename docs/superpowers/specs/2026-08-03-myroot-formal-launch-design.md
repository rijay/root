## 2. 管理层结论

myRoot 过去没有正式投入真实环境使用。本轮不是维护旧产品，而是以正式上线目标为起点，重建最小而完整的首发产品。

首发只保留四个主入口：

| 入口 | 用户价值 | 访客可做什么 | 何时要求登录 |
| --- | --- | --- | --- |
| 首页 | 看懂品牌、商品和此刻最值得做的事 | 浏览轮播和内容详情 | 首发浏览不要求登录 |
| 健康 | 了解 Root4U，完成健康评测并取得建议 | 查看 Root4U 价值与三步说明 | 点击“开始评测”时 |
| 活动 | 查看线下活动、报名并了解状态 | 浏览列表和详情 | 点击报名或取消时 |
| 我的 | 管理个人资料、会员中心入口、隐私和支持 | FAQ、客服、反馈、关于 Root | 查看/修改资料、进入我的订单或优惠券、退出时 |

“任务”不再是 Tab。旧七日计划、打卡、任务奖励、旧内部商品购买、订单匹配与退款不进入首发范围，也不为不存在的真实用户依赖建立兼容层。

## 3. 成功标准与明确不做

### 3.1 成功标准

1. 新用户能理解品牌，找到健康评测与活动，并在需要时顺畅完成登录。
2. Root 既有会员首次进入 myRoot 时能被正确识别和关联，不被误当成新会员。
3. Root4U 能完成 18 岁以上用户的初始化建档、分类、结果和安全的生活方式建议。
4. 运营无需修改代码即可维护首页、活动、内容详情、量表和推荐关系，但只能使用经过批准的配置。
5. 活动报名只有一个权威事实来源，重复操作不会产生重复报名。
6. 会员中心跳转失败、模型失败或网络超时时，小程序提供可理解、可重试的失败状态，不制造成功结果。
7. 旧任务、奖励、打卡与旧订单链路从页面、路由、后端运行注册、运营后台、Job 和测试中完整退出。
8. 本地验证、候选版本、数据迁移、微信上传、审核、发布与线上流量分别留证。

### 3.2 首发明确不做

- 不做任务、积分任务、打卡、七日计划、奖励结算或复测奖励；
- 不做第 3 天轻复测、第 7 天完整复测及相关提醒；
- 不在 myRoot 内建设商品列表、下单、支付、订单详情或退款；
- 不读取或展示会员等级、积分、余额、优惠券数量与订单摘要；“我的订单”“优惠券”只跳转 Root 会员中心对应页面；
- 不为未成年人建设监护人同意流程，Root4U 首发仅面向 18 岁及以上用户；
- 不把健康评测描述为疾病诊断或治疗，不承诺神奇功效、立刻见效或替代就医；
- 不承诺人工实时监控健康答案，不因风险答案自动创建工单或承诺主动联系；
- 不允许运营后台输入任意脚本、任意 CSS、模型密钥或任意跳转域名；
- 不花时间全面解耦、兼容或性能优化即将删除的旧产品链路。

## 4. 总体用户旅程

### 4.1 首次打开

1. 首次在该设备打开 myRoot，进入两屏欢迎页面。
2. 用户可左右滑动，也可点击“跳过”。
3. 跳过或看完后，将欢迎状态保存在本机，以后直接进入首页。
4. 清除小程序本地数据或重新安装后，可再次看到欢迎页面。
5. 欢迎页面不触发登录、不索取手机号、不加载会员或健康数据。

### 4.2 访客与受保护动作

访客可以浏览首页、Root4U 介绍、活动列表与详情，以及“我的”中的 FAQ、客服、反馈和关于 Root。

以下动作要求登录：

- 开始或继续健康评测；
- 查看健康结果和个性化建议；
- 报名或取消活动；
- 查看或编辑个人资料；
- 进入“我的订单”或“优惠券”；
- 退出登录。

触发登录时记录用户原本准备访问的页面和动作。登录完成后恢复原目标，不统一跳回首页。

### 4.3 登录后的身份分流

| 情况 | 系统动作 | 用户提示 |
| --- | --- | --- |
| 已注册 myRoot 用户 | 恢复会话并回到原目标 | “手机号已验证” |
| Root 会员中心已有会员、首次使用 myRoot | 自动关联；资料齐全则直接进入 | “手机号已验证” |
| 既有 Root 会员缺少 myRoot 必填资料 | 进入“完善资料”，不显示“欢迎注册” | 按缺失字段引导补全 |
| 两端均无账号 | 进入欢迎注册页 | 注册成功后提示“成功注册” |
| UnionID 与手机号指向不同会员 | 停止自动关联与覆盖 | “资料核验中”，提供客服入口 |

身份冲突期间仍可使用所有访客功能，但不能进入个人订单或优惠券、报名或使用个性化健康能力。

## 5. 品牌标识与用户欢迎页面

### 5.1 Root Logo 全局使用规则

- 小程序和运营后台界面只使用官方 Root Logo 中的文字字形部分，不使用左侧器皿图形；
- 不得用系统字体重新输入 `root` 代替官方字形，应从审核通过的 Logo master 裁切或导出文字部分；
- 深色与浅色背景分别使用对应的反白或深色文字版本，并保留安全留白；
- 欢迎页、首页、登录注册、默认头像、关于 Root 和运营后台均遵循同一规则。

### 5.2 视觉结构

- 两张沉浸式全屏背景图，可左右滑动；
- Root Logo 的文字字形部分固定在两张图左上角，并避开微信胶囊与安全区；
- 文案使用编辑式下三分之一布局，左对齐，背景下方有渐变保护；
- 导航点位于中下部中央；
- “跳过”固定在右下角，并避开底部安全区；
- 长文不得遮挡人像、商品主体、Logo、胶囊或操作区域；
- 375px 级别小屏、常见 iOS 和 Android 真机均需验收。

### 5.3 正式文案

第一屏：

> 欢迎加入Root Member Club<br>
> Sustained Foundation Balance

第二屏：

> 平衡不是控制，而是理解。ROOT的研究源于肠道——人体最复杂也最被忽视的系统。我们不宣称“神奇功效”，也不相信“立竿见影”的幻觉。当你选择ROOT，不是简单地服用它，而是开始与身体重新合作。真正的健康，是当身体、心智与能量重新步入节奏时，你所感受到的安稳、轻盈与清晰。人如草木，根定而生。 Root的使命，就是帮你把身体还给身体自己。

正式图片必须来自具备商业使用授权的 clean master，并提供不同设备比例所需的安全裁切版本。

## 6. 登录、注册与会员关联

### 6.1 单独登录页

页面包含：

- 左上角返回上一页和返回小程序首页；
- 中部文案：“注册Root会员探索更多可能”；
- 主按钮：“手机号快捷登录”。

用户点击主按钮后：

1. 如尚未完成隐私保护提示，先进行隐私确认；
2. 使用微信小程序标准手机号授权流程取得临时凭证；
3. 后端验证临时凭证，不信任前端自行提交的手机号；
4. 按可信微信身份与已验证手机号完成身份分流；
5. 登录、注册或资料完善完成后恢复原目标页面。

用户拒绝隐私或手机号授权时，显示原因、重试入口和返回公开页面入口，不制造成功状态。

### 6.2 注册与资料完善

| 字段 | 获取方式 | 必填 | 规则 |
| --- | --- | --- | --- |
| 我的头像 | 微信头像控件、上传或拍照 | 否 | 未授权或内容检查失败时使用 Root Logo 的文字字形部分 |
| 我的昵称 | 微信昵称控件，也可编辑 | 否 | 未授权或内容检查失败时使用“Root用户” |
| 手机号 | 上一步微信验证结果 | 是 | 只读，不允许前端修改 |
| 生日 | 微信日期选择控件 | 是 | 不得为未来日期，用于 Root4U 年龄判断 |
| 性别 | 男 / 女 | 是 | 未选择不可提交 |

底部按钮文案为“登录”。必填项不完整时提示“必填项未填写”；新用户创建成功后提示“成功注册”。重复点击只能创建一个用户。

既有 Root 会员进入的是“完善资料”，只补充缺失字段，不重复创建会员，也不展示新会员欢迎话术。

### 6.3 Member Center Link Module

`Member Center Link Module` 只向 myRoot 提供“我的订单”和“优惠券”两个固定跳转 Interface，由受控微信小程序跳转 Adapter 打开 Root 会员中心的对应白名单路径。

首发明确不读取、不缓存、不展示会员等级、积分、余额、优惠券数量或订单摘要。myRoot 不建设资产交易、订单与优惠券明细 Implementation，也不向运营后台开放任意小程序路径配置。

游客点击入口时先完成 myRoot 登录，登录成功后恢复原目标再跳转；已登录用户直接跳转。跳转失败时停留在当前页面，显示“暂时无法打开 Root 会员中心”和“重试打开”，不制造成功状态。UnionID 仍只用于可信身份关联，身份原值不得进入普通分析日志。

## 7. 首页与共用内容详情

### 7.1 首页

- 沉浸式全屏轮播，内容可以是商品图或活动说明图；
- 顶部展示 Root Logo 的文字字形部分，中下部显示导航点；
- 用户左右滑动切换，点击当前轮播进入共用详情；
- 每张轮播可配置两行或三行居中文字；
- 文字切换使用轻量过渡动画；
- 首屏先显示已发布图片和基础文案，不等待会员、健康或其他非必要数据。

### 7.2 运营配置

每张轮播最少配置：标题、两至三行文案、图片、排序、启停时间、详情内容、跳转类型和跳转目标。

运营只能从 UED 审核过的预设中选择：字体预设、字号档位、文字颜色、两行/三行、对齐方式。后台同时展示图片建议尺寸、文件大小、格式与安全区说明。

不允许任意 CSS、远程字体代码、脚本或任意域名。

### 7.3 共用沉浸式详情

首页商品/活动说明与活动 Tab 详情共用一个 `Content Module`：

- 内容由一张或多张纵向图片组成；
- 左上角提供返回上一页；
- 可点击区域由后台配置受控跳转；
- 支持小程序内页、Root 会员中心小程序路径、经平台验证且在白名单内的网页；
- 活动详情额外显示固定底部报名/状态栏；
- 图片热点只负责内容跳转，不承担活动报名事实。

发布前必须验证素材、热点区域、目标路径和域名。验证失败时阻止新版本发布，线上继续使用上一已发布版本。

## 8. 健康：Root4U

### 8.1 定位与准入

Root4U 用于健康状态评测与生活方式建议，不是疾病诊断或治疗工具。

- 健康 Tab 的品牌价值说明与三步引导允许访客浏览；
- 用户点击“开始评测”时要求登录；
- 采集健康答案前，单独取得医疗健康敏感个人信息处理同意；
- Root4U 首发仅面向 18 岁及以上用户；
- 未满 18 岁用户可继续使用首页、活动和“我的”访客功能；
- 拒绝或撤回健康同意不影响非健康功能。

三步引导固定为：

1. 确定人群分类；
2. 完成基础状态评测；
3. 选择适合自己的健康评测。

### 8.2 初始化建档 12 问

注册时已采集生日和性别，建档不重复询问。首发采用以下 12 个必填问题：

1. **这次使用 Root，最想先改善哪类状态**：排便更规律 / 腹胀反酸更少 / 睡眠和作息更稳 / 压力和精力更好 / 饮食运动更规律 / 先记录观察。
2. **当前最困扰的状态对日常影响程度**：0 无影响 / 1–3 轻微 / 4–6 明显 / 7–8 很影响 / 9–10 严重影响。
3. **安全与适用性确认**：无以上情况 / 怀孕、哺乳或备孕 / 医生要求控制饮食或运动 / 正在治疗重大或慢性疾病 / 近期手术、住院或急性病 / 血便或黑便 / 持续腹痛、发热、严重腹泻或持续呕吐 / 近期非主动明显体重下降 / 最近出现伤害自己的想法。
4. **过去 7 天排便频率**：每天 1–2 次 / 每 2–3 天 1 次 / 每周 2 次及以下 / 每天 3 次及以上且偏稀 / 频率波动大 / 不确定。
5. **过去 7 天最常见便便形态**：偏硬、颗粒状 / 成型顺畅 / 偏软、不太成型 / 稀便或水样 / 多种形态混合波动 / 不确定。
6. **过去 7 天消化感受**：无明显不适 / 腹胀或胀气 / 腹痛 / 反酸或烧心 / 餐后不适或早饱 / 恶心或食欲差 / 排便费力 / 便急。
7. **过去 7 天平均每天睡多久**：少于 5 小时 / 5–6 小时 / 6–7 小时 / 7–8 小时 / 8–9 小时 / 超过 9 小时 / 昼夜颠倒或很不规律。
8. **主要睡眠困扰**：无明显困扰 / 入睡困难 / 夜里容易醒 / 早醒 / 睡醒不解乏 / 白天困倦 / 睡前手机、工作或情绪影响 / 轮班或照护影响。
9. **过去 7 天活动和久坐情况**：几乎不运动且久坐较多 / 每周 1–2 次轻活动 / 每周 3 次及以上、每次约 30 分钟 / 工作或通勤中经常走动 / 有规律运动但久坐时间长 / 不确定。
10. **过去 7 天饮食结构**：每餐基本有蔬菜且每天有水果 / 有蔬菜但水果、全谷物或豆类较少 / 外卖、加工食品较多 / 甜食或含糖饮料较多 / 进餐不规律或晚餐较晚 / 食量波动较大。
11. **过去 7 天饮水和饮品情况**：饮水较充足，少喝含糖饮品 / 饮水偏少 / 常喝含糖饮料 / 下午或晚上喝咖啡、浓茶或能量饮料 / 经常饮酒或睡前饮酒 / 不确定。
12. **过去 7 天压力和精力**：状态稳定 / 压力较大但能恢复 / 持续疲惫、精力低 / 情绪低落或兴趣下降 / 容易焦虑、紧张或难放松 / 最近有明显生活事件 / 不愿回答。

这 12 问进入真实数据环境前，由产品、健康内容和隐私负责人共同签署版本。首发不包含第 3 天或第 7 天复测、任务、打卡、奖励和提醒。

### 8.3 分类与结果

系统先判断安全状态，再进行分类。常规主分类包括：

- 基础状态维护型；
- 肠道规律关注型；
- 腹胀反酸关注型；
- 睡眠节律关注型；
- 压力活力关注型；
- 活动饮食调整型；
- 生活方式波动型。

建档结果包含：主分类、辅助标签、1–3 条优先建议、安全状态与推荐量表。用户目标和实际状态冲突时，以安全风险和影响程度优先。

### 8.4 安全分流

安全与适用性题至少覆盖：孕期/哺乳/备孕、医生要求控制饮食或运动、重大或慢性疾病治疗、近期手术/住院/急性病、血便或黑便、持续腹痛/发热/严重腹泻/持续呕吐、近期非主动明显体重下降、伤害自己的想法。

处理规则：

- 血便或黑便、持续严重症状、明显非主动体重下降、伤害自己的想法等风险答案：停止普通 tips 与常规推荐，仅展示经过批准的固定求助或就医指引；
- 孕期/哺乳/备孕、正在接受重大或慢性疾病治疗、近期手术/住院/急性病等特殊适用情况：停止自动生成普通建议，展示固定的谨慎说明与咨询专业人士指引；
- Root 不承诺人工实时监控、不自动创建人工工单、不承诺主动联系；
- 用户仍可返回非健康页面，风险答案不能进入普通运营分析或普通前端日志。

### 8.5 生活方式建议

用户完成初始化建档或后续评测后，`Lifestyle Advice Module` 生成并保存一个建议池：

1. 只发送完成建议所需的最少健康字段；
2. 不发送手机号、昵称、UnionID、OpenID 等直接身份信息；
3. 模型输出必须经过结构、禁用表达和健康安全检查；
4. 合格建议进入版本化建议池；
5. 用户每次进入健康页，从当前建议池轮换展示三条；
6. 只有资料或评测结果发生变化时才重新生成，不在每次打开页面时实时调用模型；
7. 模型不可用、超时或输出不合格时，使用健康内容负责人批准的固定 tips。

`Lifestyle Advice Module` 的 Interface 同时支持模型 Adapter 与固定内容 Adapter。模型密钥仅存在于后端秘密管理中。

### 8.6 推荐量表

运营后台配置“主分类/辅助标签 → 量表版本”的推荐关系。每份量表必须具备名称、版本、适用人群、题目、选项、计分规则、结果分层、建议内容、审批人、生效时间和退役时间。

已发布版本不可原地改写；历史结果始终引用用户作答时的版本。

## 9. 活动

### 9.1 页面体验

- 活动 Tab 使用参考 App Store Today 信息密度的卡片列表；
- 卡片展示主视觉、标题、时间/地点摘要与报名状态；
- 点击进入与首页共用的沉浸式详情；
- 详情底部固定显示报名按钮或当前状态；
- 图片热点仅用于补充内容、购买或相关页面跳转。

### 9.2 唯一报名事实

myRoot 是首发活动报名、取消和状态的唯一权威来源。Root 会员中心或公众号跳转只用于购买或补充内容，不创建第二套报名事实。

报名成功、审核中、已报名、已取消、已满、已结束等状态由后端权威结果决定。提交结果未知时，按请求编号查询最终状态；重复点击与重试不得重复占用名额。

活动容量、报名时间、取消截止、审核方式和状态流转均需要版本化配置与审计。

## 10. 我的

### 10.1 访客版本

未登录用户可以看到 Root Logo 或访客状态，并使用：

- 常见问题；
- 联系客服；
- 建议与反馈；
- 关于 Root；
- 版本号。

“我的订单”和“优惠券”在头像下方纵向单列。访客点击时进入登录流程，登录完成后恢复原入口并跳转 Root 会员中心。

### 10.2 登录版本

登录后页面展示：

- 头像与昵称；
- 头像下方纵向单列“我的订单”和“优惠券”，点击后跳转 Root 会员中心对应页面；
- 常见问题、联系客服、建议与反馈、关于 Root；
- 退出登录；
- 版本号。

退出登录只清除当前会话和受保护的本地缓存，不删除账号，也不清除欢迎页已读状态。

### 10.3 隐私与账号

“注销 myRoot 账号”位于“关于 Root → 隐私与账号”二级页面，不放在“我的”主列表中。

注销流程必须：

1. 清楚说明注销范围、后果和预计处理时间；二次确认后即受理，不设置隐蔽的营销挽留步骤；
2. 明确注销 myRoot 不自动注销 Root 会员中心账号或抹除依法需保留的交易记录；
3. 二次确认用户意图；
4. 立即停止新的非必要采集并使当前会话失效；
5. 删除可删除数据，对依法需保留数据做限制处理或匿名化；
6. 提供可核验的处理状态与客服入口。

## 11. Module 与数据设计

### 11.1 Module 清单

| Module | 对调用方提供的 Interface | 主要 Adapter |
| --- | --- | --- |
| Session Module | 登录、注册、资料完善、恢复原目标、退出 | 微信身份、手机号验证、用户存储 |
| Member Center Link Module | “我的订单”“优惠券”固定白名单路径与跳转结果 | 微信小程序跳转 |
| Content Module | 欢迎内容、首页轮播、沉浸式详情、受控跳转 | 媒体存储、发布记录 |
| Activity Module | 活动列表、详情、容量、报名、取消与权威状态 | 活动存储、通知通道 |
| Assessment Module | 量表版本、作答、计分、分类、结果与推荐 | 健康数据存储、量表发布记录 |
| Lifestyle Advice Module | 建议池、三条轮换建议与固定降级内容 | 已批准模型、固定内容库 |
| Profile Module | 头像昵称、生日性别、隐私账号、支持、退出与版本 | 用户存储、微信头像昵称控件 |

每个 Module 只暴露一个稳定 Interface。只有存在两个真实 Adapter 时才建立 Seam；内部 Implementation 不向页面泄漏外部系统细节。

### 11.2 关键数据流

身份流：

`微信临时凭证 → Session Module 验证 → 可信身份/手机号匹配 → 新用户、既有会员或冲突状态 → 恢复原目标`

健康流：

`18+ 判断 → 健康敏感信息单独同意 → 版本化作答 → 安全判断 → 常规分类或固定风险指引 → 建议池/量表推荐`

活动流：

`活动详情 → 登录检查 → 带请求编号提交 → Activity Module 幂等写入 → 权威状态回读 → 页面固定底栏更新`

内容流：

`运营草稿 → 系统校验 → 小程序预览 → 二次确认 → 生成不可变发布版本 → 小程序读取当前版本 → 失败时保留上一版本`

### 11.3 数据分区

- 身份凭据、会员资料、健康答案、普通分析事件和业务审计分别保存；
- 普通分析事件不得记录手机号、微信身份原值、健康原始答案或凭据；
- 健康结果引用量表、计分、模型、提示词和固定内容的版本；
- 发布内容不可原地覆盖，便于追溯用户当时看到的内容；
- 数据库历史 migration 不改写，删表或归档必须通过新的 forward migration。

## 12. 运营后台

运营后台沿用现有 Vue 3、Vite 与 Element Plus Admin 技术底座。首发只设置一个后台角色，不建设角色、权限或会员设置界面；登录与基本访问控制继续作为后台运行要求。

| 一级导航 | 二级能力 | 首发要求 |
| --- | --- | --- |
| 发布工作台 | 发布总览 | 只展示内容版本及其校验、预览、二次确认与发布状态；代码部署、微信审核、正式发布和线上流量分别展示，不合并为一个“已上线”状态 |
| 内容运营 | 欢迎页、首页轮播、共用详情 | 图片尺寸提示、文字预设、排序、定时上下线、多图内容、热点区域、跳转白名单、失效检查与小程序预览 |
| 活动运营 | 活动管理、报名记录 | 活动内容、详情、时间地点、名额、报名与取消规则；报名记录是权威事实的只读运营视图，手机号脱敏，导出留审计 |
| 健康运营 | 初始化建档、量表管理、推荐规则、生活方式建议 | 12 问与安全分流；题目、计分和结果分层共同版本化；人群到明确量表版本的映射；已批准模型配置与固定内容降级 |
| 用户与审计 | 用户查询、操作审计 | 用户查询只显示最少注册与资料信息，不显示会员资产或健康原始答案；审计记录不可原地修改，不记录密钥、凭据、微信身份原值或健康原始答案 |

所有内容遵循“草稿 → 系统校验 → 小程序预览 → 二次确认 → 发布”。已发布版本不可原地修改，只能复制为新草稿。内容责任人的签署记录属于内容发布依据，不引入第二个后台角色或独立角色审批流。

旧任务、奖励、结算、七日计划及旧购买配置必须从菜单、路由、后端运行 Registry、Job manifest、测试与配置中一起退出。

## 13. 异常恢复

| 异常 | 用户看到什么 | 系统行为 |
| --- | --- | --- |
| 隐私或手机号授权被拒绝 | 原因说明、重试、返回公开页面 | 保留原目标，不创建会话 |
| 登录或读取超时 | 可重试的明确失败提示 | 不制造登录成功，不清空公开页面状态 |
| 身份匹配冲突 | “资料核验中”与客服入口 | 停止自动关联、覆盖和个人订单/优惠券跳转 |
| Root 会员中心跳转失败 | “暂时无法打开 Root 会员中心”与“重试打开” | 停留当前页面，不读取会员资产，不影响首页和活动 |
| 活动提交结果未知 | “正在确认报名状态” | 按请求编号查询权威结果，不重复写入 |
| 首页内容读取失败 | 上一已发布版本或明确空状态 | 不阻塞其他 Tab |
| 素材或跳转不合法 | 后台发布失败原因 | 新版本不生效，保留线上上一版 |
| 模型不可用或输出不合格 | 已批准固定 tips | 不显示空白，不直接展示未审输出 |
| 健康风险答案 | 固定求助/就医或谨慎指引 | 停止普通 tips，不承诺人工监控 |
| 注销处理中 | 明确处理状态与客服入口 | 会话失效、停止新采集、按规则处理数据 |

4. 以新的 forward migration 归档或删除；
5. 单独取得数据库变更批准，并验证恢复步骤。

## 15. 开发顺序

### R1：清场与产品骨架

完成四 Tab、欢迎页和新路由清单；删除旧任务、奖励、打卡、订单匹配和退款的用户可达入口。

退出条件：路由扫描、分享路径、后台菜单和真机导航均无旧入口。

### R2：身份

完成独立登录、注册、资料完善、原目标恢复、既有会员关联和冲突状态。

退出条件：新用户、已注册 myRoot、既有 Root 会员、拒绝、超时、重复提交和身份冲突均可恢复。

### R3：内容

完成 `Content Module`、首页轮播、共用沉浸式详情、受控跳转与运营发布。

退出条件：运营可完成草稿、系统校验、小程序预览、二次确认、定时发布和下线；非法素材或跳转无法上线，已发布版本不可原地修改。

### R4：活动

复用并收窄已有活动事实，完成 Today 风格列表、共用详情、固定报名栏和权威状态。

退出条件：并发名额、重复提交、取消截止、弱网和结果未知恢复通过。

### R5：Root4U

完成 18+ 与健康同意、初始化 12 问、版本化分类、建议池、安全分流和推荐量表。

退出条件：内容、隐私与技术验收通过；模型失败及风险答案均有固定降级。

### R6：我的与运行清退

完成访客/登录版“我的”、“我的订单”与“优惠券”固定跳转、隐私账号与注销；删除旧后端运行注册、后台入口和 Job，并完成旧表只读盘点。

退出条件：四 Tab 首发范围闭合，全仓与运行时均无旧产品可达路径。

旧产品的全面性能基线不再作为 R1 前置任务。每个新切片只测量该切片保留的关键旅程，避免为即将删除的旧逻辑消耗重整成本。

| Root 会员中心“我的订单”“优惠券”正式小程序路径与真实测试账号 | 会员中心负责人 | 两个跨小程序入口上线 |
| 网页/公众号内容目标与平台允许条件 | 运营/微信管理员 | 对应跳转类型上线 |
| 当前 CloudBase、MySQL、微信审核与线上版本回读 | 技术/发布负责人 | 任何正式上线声明 |

这些材料不阻止删除明确废弃的旧功能，但会阻止对应新能力进入正式发布。

## 19. 对抗式自审

交付前按最容易翻车的方向反查：

1. **只隐藏，没有删除**：同时检查前端路由、后端运行 Registry、Job manifest、运营后台菜单、权限与测试。
2. **把跳转需求重新扩成会员资产同步**：首发只保留“我的订单”“优惠券”两个固定跳转，不新增等级、积分、余额、数量或订单摘要读取。
3. **健康风险被普通建议覆盖**：安全判断必须先于分类与模型调用；风险答案只能进入固定指引。
4. **运营配置成为线上注入入口**：后台只提供经过批准的预设和白名单，不允许任意代码、样式、密钥或域名。
5. **把一个发布状态说成全部上线**：本地、候选、迁移、上传、审核、发布和流量分别留证。

本规格已经消除以下歧义：健康介绍允许访客查看；Root4U 为 18+；myRoot 是活动报名唯一权威来源；“我的”不展示会员资产，只提供“我的订单”“优惠券”固定跳转；高风险不承诺人工监控；账号注销位于隐私与账号二级页；首页文字使用 UED 预设；首发不做第 3/7 天复测。

### 21.3 运营后台信息架构

后台导航固定为：

1. 发布工作台；
2. 内容运营：欢迎页、首页轮播、共用详情；
3. 活动运营：活动管理、报名记录；
4. 健康运营：初始化建档、量表管理、推荐规则、生活方式建议；
5. 用户与审计：用户查询、操作审计。

首发不提供任务、打卡、奖励、结算、订单匹配、售后、角色权限或会员设置菜单。会员等级、积分、余额、优惠券数量和订单摘要既不进入后台用户查询，也不进入小程序页面。

### 21.4 关键运营规则

- 共用详情建立内容库，首页和活动只引用内容版本，避免重复编辑；
- 已发布内容不可原地修改，只能复制为新草稿；
- 活动报名事实由 `Activity Module` 维护，后台报名记录只是其运营视图；
- 初始化建档 12 问和安全分流必须经过内容、隐私与技术三方签署后才可用于真实数据；
- 量表的题目、选项、计分和结果分层作为一个版本发布；推荐规则只能引用明确的已发布版本；
- 生活方式建议通过已批准模型 Adapter 或固定内容 Adapter 生成，后台只选择模型配置，不展示或输入密钥；
- 用户查询只提供解决账号问题所需的最少信息；操作审计不存放凭据、敏感原值或健康原始答案；
- 发布确认一次只改变一个内容版本状态，不自动触发代码部署、微信送审、正式发布或线上切流。
